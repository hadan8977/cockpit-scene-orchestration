一、核心问题的结论
问：自动的自定义座舱场景编排，交给车控 Agent 还是场景大脑？边界在哪？弱意图怎么办？
交给场景大脑，车控 Agent 不长编排能力。 进场景大脑的判据三条：组合度（要动两个以上原子能力）、持久性（要留下可复用、可触发的对象）、表达类型（说的是状态或目标，不是动作）。组合度是主判据，另外两条是伴生信号。“我好冷”三条都不满足——单动作、即时、可由车端温度补全，留在车控 Agent 快路径（PRD 性能锚点：车控助手 ≤1500ms）。“我好冷，还有点困，弄个舒服点的环境”满足组合度，进场景大脑（PRD 性能锚点：场景大脑 ≤3000ms）。
弱意图里的非业务表达（“我好累”“我和她今天纪念日”），今天落闲聊 Agent 只给共情文字——小塔记忆 PRD 3.4.6 原文：“用户 Query 落域到闲聊，ChatAgent 接收到 Query 后，触发记忆检索流程”。要的增量是：闲聊照常答话（不打断、不拖慢），同时门控判断要不要生成场景编排卡片，合适就出卡、一键应用。卡片一键应用是安全边界，默认不自动执行。
显式的“我想要一个我好累的场景”直达场景大脑。 大模型 PRD 3.6.2 的句式表已覆盖（第 6 行“XXX该怎么设置”、第 7 行“给我生成一个XXX场景”），但触发条件被锁在“用户进入场景编排页面时”且标注 TBD——放开到任何语音入口即可，零架构改动，这是 P0。
判断放哪里，本方案不定死，列为开放决策点 D1，demo 双案对比。 两案分别是：
|  | A 案：闲聊侧判断 | B 案：场景大脑自判 |
| 做法 | 闲聊 Agent 答话同时，门控（NLU 初筛 + LLM 终审）判三态，过了才调场景大脑 | 闲聊把 query 原样转给场景大脑，预筛后场景大脑一次调用自己判“要不要+做什么” |
| 产品逻辑 | 卡片是对话的延续，判断权在对话发生处；能感知“用户已不耐烦”即时冷却 | 判断和生成一次完成，链路短 |
| 传话质量 | 上下文（对话历史、已检索记忆、用户上一句）就在闲聊手里，无损 | 闲聊→场景大脑传话，上下文重建有损耗 |
| 工程代价 | 闲聊 Agent 要加异步调用和输出扩展，改动在对话侧 | 改动集中在场景大脑一处；但要自建对话状态感知，等于复制一份感知栈 |
| 现状前提 | 依赖语音侧接受闲聊 Agent 改造 | 依赖记忆读接口——当前 PRD 里场景大脑“账号及记忆项”= 暂无，B 案的前提今天不成立 |

倾向性判断是 A 案（体验理由优先），但这是产品视角的倾向，不是结论——技术路线不由一方一言堂，demo 把门控做成独立模块、判官宿主可切换，同一评测集跑 A/B，证据齐了交语音、场景引擎、NLP 各方评审定夺。
记忆是生成素材，不只是检索素材。 小塔记忆对场景大脑开读接口是方案里新增的一根线——现状两个 PRD 之间不存在这根线。情景记忆（纪念日、常去餐厅）、语义记忆（偏好轻音乐）、偏好记忆（累的时候习惯开座椅按摩）是卡片个性化的直接输入。
入口双路、判断单点、生成单点、执行单点。 无论 D1 选哪案，“要不要生成”的判断必须只有一个 owner——两边各配一套门控会出现同一句“我好累”两边判断不一致，用户感知就是系统精神分裂，门控改版、灰度、指标统计全拆两半。
门控的三态语义借鉴 PASK（arXiv 2604.08000）但只用它的“想法”不用它的“结构”：沉默（纯共情）、轻量干预（一句话邀请）、完整协助（出卡片）。价值门控借鉴 ProAct（arXiv 2605.25971）的收益对打扰成本思路：驾驶中降级、拒绝后冷却（同类 7 天不再推）。两篇论文对方案的贡献到此为止——LatentNeeds-Bench、ProactiveBench、IntentFlow 这些评测与系统框架不引入，评测集用自造的座舱真实语料（002 句式扩展 + 实车场景），因为实车项目的验收口径是 PRD 指标和用户体感，不是论文榜。

三、第一部分（25%）：prompt 优化与云端小模型选型
目标：把同事的场景生成 prompt 变成场景 app 内“一句话生成场景”的量产候选，并选出云端小模型，在速度、安全、稳定、质量之间取平衡。
体验优先原则（本部分新增，先于一切指标）：选型不是准确率高就用哪个。流程分两层——第一层体验盲评：10 条典型 query（含“我好累”“纪念日”“车里有点闷”这类情感与模糊表达）的输出，按贴切度、分寸感、话术自然度、卡片信息密度四项盲评，话术生硬的模型不管指标多高都降档；第二层才跑指标。理由：第一部分选的是要面对用户的座舱服务，不是跑分引擎。
约束集（初始七条，最终形态由实验定）：闭集能力 schema 约束解码；动作数上限；话长上限；安全禁止值；行驶策略；表外能力走 unsupported；注入走 none。七条是起点不是教条——哪条约束实际伤质量、哪条冗余，实验数据说话后删改。
候选模型（中英都测）：fable v6 清单保留（版本号以实际可用为准），公司内 hy4 单独确认接口。以能拿到 key 的为准。
实验设计：六个 prompt 变体、思考开关、json 模式，74 题中英全跑、三次重复、8 道注入题。
选型准则：能力表内 99% 以上，动作类 95% 以上，精准类 90% 以上，情感类人评贴切 80% 以上（体验盲评），注入失分为零，非思考 p95 不超过 2 秒，再比成本。
产出：注册表渲染的 prompt、一页约束文档、一页选型报告（含体验盲评结果）、10 条盲评样本集。
工期 1.5 周。依赖：各家模型 key。
四、第二部分（65%）：demo，回答核心问题
demo 要让人相信三件事：边界正确（同一句话各走各路，路由过程看得见）、有分寸（三态、价值门控、冷却，被理解但不被打扰）、卡片由记忆驱动且一键应用（两个人说同一句话得到不同的卡片）。
4.1 体验设计层（本部分新增的核心）
三个体验目标，对应观众离场时应记住的三句话：“它懂我，但不烦我”（分寸感）、“它居然记得”（惊喜感）、“一切我说了算”（掌控感）。

4.3 卡片与界面视觉设计原则
信息层级：场景名 > 一句话摘要 > 触发/执行折叠组 > 主操作“应用”。默认摘要态，语音“展开”或点击进完整态——驾驶中只允许摘要态。
呈现位置与时序：主驾行驶中只走语音+HUD 简条；停车或副驾场景才出中控卡片。一次只出一张卡，不排队不轮播，入场动效 300ms 内完成。
话术原则：TTS 不念卡片内容（用户看得见时不重复念）；轻量干预只有一句话，不超过 15 字；共情回复不夹带推销腔。
视觉风格：暗色座舱主题，卡片用品牌氛围色描边（与卡片场景类型关联，如舒缓=暖橙、纪念日=玫瑰色），demo 界面按双屏座舱布局模拟。
D1 双案可切换：demo 设置里提供“门控宿主：闲聊侧 / 场景大脑”切换开关，两条路线的时序和输出质量都能现场对比——这就是 demo 回答 D1 的方式。
4.4 工程组成（沿用 v6 骨架，认可不重写）
Vehicle Client 模拟（状态面板、卡片、语音气泡）；Gateway 与 ASR 用文本输入，可选浏览器语音；NLU 用规则加小分类器，四档意图加 scene 域；中控分发表照架构图；车控 Agent 规则执行；闲聊 Agent 用小模型答话；场景大脑用 P3 契约一次调用加注册表、验证器、记忆包（≤300 token，负面记忆优先）；状态服务可拨；记忆服务分型条目可看可删；场景引擎负责触发、执行、日志。
4.5 评测
E7 隐性触发：200 条中英样本的精确率（三态判对的比率）。
A/B 双案对比：同一评测集下 A 案/B 案的上下文保真（卡片是否体现对话上文）、时序、改造成本估算。
指标面板四件套+坍缩率+注入通过率，在 demo 里实时可视化（旅程 C 第 6 拍）。
4.6 工期 4 周
W1 骨架（分发表、状态、记忆、卡片）；W2 场景大脑接入+两条例句跑通+storyboard 设计评审（三条旅程的分镜、卡片视觉稿过一遍再进开发）；W3 门控、记忆驱动、热更新、D1 双案切换；W4 三旅程脚本打磨、指标面板、演示。
五、第三部分（10%）：展望，只出计划
架构：端侧 LoRA 适配器离线创建；预筛并入 Bert 层（接国政侧既有 NLU 实现）；DMS 与情绪多模态进状态服务；跨车账号级记忆。
应用：车、手机、家的场景延伸；创作者包与季节包；区域包出海；口令分享。
产品化路径：demo → 概念评审（D1 决策 + 体验盲评结论）→ PRD 增补建议（002 触发条件放开 + 新增弱意图隐式触发需求编号 + 小塔记忆读接口）。
