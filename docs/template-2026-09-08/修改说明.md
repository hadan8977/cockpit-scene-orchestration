## 怎样调整详略

| 内容 | 本版处理 | 阅读时的作用 |
| --- | --- | --- |
| 产品背景 | 压缩为问题、定位、验证重点三个短段 | 先理解产品解决什么问题 |
| 用户与企业价值 | 分点写具体收益，保留未验证的限定 | 快速识别目标，不反复解释同一价值 |
| 处境建议 | 保留扬尘案例，用步骤说明判断过程 | 看懂为什么此刻建议、用户接下来做什么 |
| 应用、保存、自动使用 | 集中列一张操作对照表，关键区别加粗 | 防止把不同入口的“好”理解成相同授权 |
| 接管与撤销 | 分为三个规则，并保留手动调灯案例 | 读者可直接判断撤销后的设备状态 |
| 技术和历史材料 | 通过第 7 章链接承接 | 查证时可追溯，正文不被版本号和旧争议打断 |

加粗主要用于产品重点、授权差异和会改变操作结果的限制；步骤使用编号，对比使用表格，背景保留短段。没有把每句话都改成同样长度的要点。

## 内容上补了什么

为填写模板已有位置，补入了官方竞品对照、功能编号、信号需求和埋点定义。这些内容与上一版规则对应；新增编号、埋点名仅用于文档和联调，不代表代码已实现。竞品事实在正文就近引用，产品借鉴与厂商事实分别表述。

沿用的关键决定包括：四种入口；观察与快存的现有模拟流程；保存不自动授权执行；取消固定三秒试演；人工接管优先；处境建议两动作门槛仍待验证。没有因为压缩文字而取消限制或扩大授权。

当前交付为可在 GitHub 直接阅读的 Markdown 正文，按 Word 模板的章节和字段组织；并非已排版、逐页验收的 DOCX。版本、参数及原图资料沿用上一轮的核对记录。
