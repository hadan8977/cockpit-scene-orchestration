# 最终结论与整体计划 v7：边界、判断怎么做、硬约束、体验与 storyboard

2026-09-04。对 v6 的三处修正：论文降为启示，架构按"契约固定、宿主可换"写，给座舱里别的业务留位置；公司 v7 报告逐条核实，分歧处写明我的理由；demo 从功能演示改成体验叙事，场景重选，补 storyboard、视觉、动效、话术。你的原则没变：边界界定、主动克制、预设是地板、隐私先一步、理解意图。

## 一、结论

**1. 编排归场景大脑，动作归车控 Agent，安全域压过两者。** 进场景大脑看三条：组合度为主，指要动两个以上元素；持久性与表达类型伴生，指留下可复用的对象、说的是状态或目标。我补两条：一是上位规则，困倦、孩子留车、雨天车窗这类安全表达先走安全与车控的固定动作，场景大脑不在安全情境里做创作，只在其后补舒适；二是指令式的组合直接做，陈述式的弱意图才走三问，"别吵醒他"是前者，"她说还要二十分钟"是后者。

| 话 | 去向 | 形式 |
|---|---|---|
| 热死了 | 车控 Agent，MAX AC，1.5 秒内 | 直接做，不出卡 |
| 有点困 | 安全与车控的固定提神动作 | 直接做，语音建议休息 |
| 别吵醒他 | 场景大脑，立即布景：音量、后排灯、导航播报、风量 | 直接做，不说话，灯光轻应一下 |
| 她说还要二十分钟 | 闲聊答话；场景大脑异步判断 | 灯语加一句，同意后试演 |
| 做一个雨夜回家的场景 | 场景大脑，scene 域直达 | 卡片，可改可存 |

**2. 弱意图的答案：答话归闲聊，布景归场景大脑，呈现只有一个管家。** 公司报告担心两边判断打架，所以要求判断单点。我的判断是单点应当放在呈现上：判断做成漏斗，每一级只能说"不"，不能说"出"；呈现管家只有一个，按状态、预算、冷却决定沉默、灯语加一句、卡片三种形式。这样判官放闲聊侧还是场景大脑侧都不会精神分裂，宿主可以按团队边界换。呈现管家应当是座舱级的：用车助手的提醒、娱乐的推荐、场景的卡片都走它，预算按整车算，不按功能算，否则五个功能各自每周两张卡，用户一周吃十张。

**3. "要不要有场景"怎么判断，三问。** 见第二节，一张表看懂。

**4. 显式请求直达。** "我想要 xxx 的场景"、场景名、口令、"记住现在这样"从任何语音入口和场景 app 的输入框直达场景大脑，续聊留在场景大脑改一处。

**5. 除了弹卡片，用户感到的六个变化。** 这是回答"手机也有卡片"的部分。

| 变化 | 用户感到什么 | 手机卡片做不到的原因 |
|---|---|---|
| 听懂话外音，回一句、布一景 | 我随口一说，车懂了，还引用我的话 | 手机卡片是应用快捷方式，不改变空间 |
| 灯语先于卡片 | 它有想法时灯轻轻呼吸一下，我可以理都不理 | 手机只有通知，没有环境这个媒介 |
| 试演三秒，不用读卡 | 灯和声先淡进来，我说"就这样"或"不用" | 手机要读要点，车要的是感受 |
| 有始有终 | 上车淡入、到家谢幕，音乐渐弱灯渐亮 | 手机的场景是开关，车的场景是时间线 |
| 一句话改一处，改了就记住 | "灯再暗点"只动灯，下次默认更暗 | 手机改设置要进菜单 |
| 记得，但你说了算；有客人时不用你的私事 | 卡片上写着用了哪条记忆，长按即删；客人上车自动收起 | 手机没有"车上还有谁"这个概念 |

**6. 架构：契约固定，宿主可换。** 固定的五样：场景对象模型，含名字、条件、六元素动作、时间线、记忆引用；能力注册表与验证器；"布景机会"事件的字段；呈现管家唯一；记忆逐条可见可删、按人隔离。可换的四样：一级判官的宿主，可以是 Bert 头、域规则或闲聊模型顺带输出；二级判官，可以是场景大脑一次调用，也可以退化为只生成不判断；呈现管家的宿主，场景引擎或车机通知中心；执行通道，现有 Sub Agent 或规则引擎直连。D1 我推荐一级放 NLU、二级放场景大脑：闲聊 Agent 的 prompt 不必为场景改，每句闲聊不多付时延；场景大脑手里有注册表，才答得了"车能不能帮上"。语音团队若坚持闲聊侧顺带输出三个字段，事件字段不变，demo 里一个开关切换。

**7. 硬约束五层，模型只管"怎么想"。** 注册表闭集、schema 约束解码、验证器、执行策略、评测门，详见第四节。prompt 里只剩理解方法与语法，不承担安全。

## 二、判断机制：三问、三态、三个例子

先说清 A 案与 B 案。两案的一级判官都是 NLU 层已有的域、意图和置信度输出，这一步不新增模型。区别在二级判官谁跑 LLM：A 案让闲聊模型答话时顺带多输出三个字段，值不值得布景、置信度、三态；B 案让场景大脑在生成场景的同一次调用里输出相关度，相关度低就沉默。两案用户看到的东西一样，差别在改谁的 prompt、谁看得到什么上下文。

| 问 | 谁答 | 看什么 | 门槛 [设计值] |
|---|---|---|---|
| 一、这句话里有没有车能接的状态或目标 | NLU 层布景分，或域规则 | 句子本身 | 布景分不低于 0.8；命令类域不进 |
| 二、此刻合不合适 | 呈现管家 | 状态服务、预算、冷却、静默期 | 高负荷驾驶不进；每周卡片不超过 2 张；同类被拒 7 天不进；两次忽略停 30 天；前 14 天只学不说；作息异常日不进 |
| 三、值不值得 | 场景大脑一次调用 | 原话、最近两轮、记忆包、注册表、当前舱内状态 | 相关度不低于 0.7；生成的场景要改动两个以上元素且与当前状态不同；命中负面记忆即沉默 |

三问全过，呈现管家定形式：行驶中只给灯语加一句；停车或副驾屏可给卡片；错过的卡片进场景中心的"它的想法"收件箱。

| 话 | 状态 | 一问 | 二问 | 三问 | 结果 |
|---|---|---|---|---|---|
| 又堵了，烦死了 | 行驶，主路 | 0.55，不过 | 不评 | 不评 | 沉默；闲聊答一句 |
| 她说还要二十分钟 | 停车，商场地库 | 0.9 | 停车，预算有 | 0.85，等人场景改动 4 个元素，无负面记忆 | 灯语加一句 |
| 别吵醒他 | 30 公里时速，后排有人 | 0.95，指令式目标 | 低负荷 | 0.9，改动 3 个元素 | 立即布景，不说话 |

## 四、第一部分（25%）：硬约束下的"一句话生成场景"，与模型选型

**4.1 用户看到的。** 场景 app 里一个输入框，说或写一句话。半秒内先出现一行"听到的"，引用原话；随后六元素 chips 逐个出现；被裁掉或改过的 chip 灰显并写理由；三个键：试一下、就这样、不用；再说一句只改一处。内部版多一个模型与 prompt 的下拉框和一条时延条，A/B 现场切。

**4.2 硬约束五层。** 这才是"有硬约束"的意思，prompt 是第零层。

| 层 | 管什么 | 例子 | 状态 |
|---|---|---|---|
| 注册表 | 能力闭集、安全级 A/B/C、禁止值、上下线 | 下线香氛后 prompt、schema、验证器同时失效 | 已做，eval/registry.py |
| 约束解码 | 模型物理上写不出表外能力和非法取值 | actions 只能取 enum 里的名字与取值 | schema 已生成；各家 API 是否支持严格 schema [待核实] |
| 验证器 | 安全禁止值、行驶策略、动作数、话长、去重、注入标记 | 关行人警报音被丢弃并标法规；行驶中车窗改成一小缝 | 已做，eval/validator.py |
| 执行策略 | 执行前再查注册表状态、与当前状态冲突消解、一键应用、10 秒内撤销、行驶中延后 | 试演三秒后才落座椅动作 | demo 内做 |
| 评测门 | 74 题中英、8 道注入题、坍缩率，达标才上线 | 注入失分不为零即不上 | 已做，eval/run_eval.py |

**4.3 prompt 里留什么。** 先写理解再写动作；六元素语法，不放预设清单；六个结构互不重复的例子；中英各自的 say 上限；unsupported 与 clarify 两个出口。删掉的：人设、威胁语、格式说教。

**4.4 选型：先过体验门，再比硬指标，最后比成本。**

| 关 | 内容 | 通过线 [设计值] |
|---|---|---|
| 体验门 | 10 句盲评，贴切、分寸、话术、密度四项；服务项：续聊改一处、表外走 unsupported、三次重复结构一致、中英一致 | 任一项不及格出局，不看指标 |
| 硬指标 | 能力表内、动作类、精准类、情感类贴切、注入、首字、p95 | 99%、95%、90%、80%、零失分、0.6 秒、2 秒 |
| 成本 | 每次调用价格与并发限制 | 只用于排序 |

候选：DeepSeek V4 Flash 为主；Qwen3 Flash、豆包 Seed Flash、GLM-4.7-Flash、Kimi K2.7 highspeed、hy4 为对照，版本以能拿到 key 为准。变量：六个 prompt 变体、思考开关、json 模式、严格 schema 有无。产出：注册表渲染的 prompt、一页约束文档、一页选型报告、盲评样本集。工期 1.5 周。

## 五、第二部分（65%）：demo

**5.1 要证明三件事，观众离场记住三句话：** "它听懂了话外音"，"它有分寸"，"我说了算"。

**5.2 场景怎么选。** 标准四条：高频且全球通用；车当房间用的时刻，编排才有空间；能同时演边界与分寸；不用个人化的偶发例子。选定五个：暴晒后上车与堵车做边界对照；后排孩子睡了；地库等人；周六造一个雨夜回家的场景；客人上车。等人与接送孩子是停车与低速时段里最常见的两个时刻 [推断，需用车日志验证]。

**5.3 旅程一「一个傍晚」**

| 拍 | 时刻与画面 | 用户说 | 车做 | 用户感到 | 演的是 |
|---|---|---|---|---|---|

| 2 | 18:05，主路堵车 | 又堵了，烦死了 | 闲聊答一句；侧栏显示三问在第一问止步 | 没被推销 | 分寸：沉默也是决定 |
| 3 | 18:20，接完孩子，后排睡着 | 别吵醒他 | 音量降、后排灯灭、导航改主驾侧小声、风量限 3 挡；不说话，灯光暗一下算回应 | 它懂"轻" | 指令式组合直接布景 |

**5.6 体验与视觉规范**

| 项 | 规范 |
|---|---|
| 画布 | 浏览器一页：顶部通长氛围灯带；左仪表、中 15.6 寸中控、右副驾屏；底部语音气泡与输入框；右抽屉路由侧栏，左抽屉记忆抽屉，均可关，给决策层看时关掉侧栏 |
| 三种形式 | 沉默：只在侧栏留决定；灯语加一句：灯带一次呼吸 2 秒，话不超过 15 字，英文不超过 8 词，不上屏；卡片：默认摘要态三行，展开态才有 chips；一次一张，不排队不轮播，15 秒退场进收件箱 |
| 卡片解剖 | 名字；"听到的"引用原话；六元素 chips；记忆 chips "用到了…"，长按删；裁剪 chips 灰显带理由；三键试一下、就这样、不用；"为什么"小字 |
| 动效 | 卡片进 300 毫秒出 200 毫秒；场景灯 2 秒淡入、声 3 秒淡入、座椅最后动；谢幕 3 秒；灯语无音效 |
| 声音 | TTS 不念卡片；哄睡态 TTS 降 12 分贝；试演只动灯与声，不动座椅 |
| 话术 | 引用用户的词；不夸不推销；不解释自己，除非被问"为什么"；被撤销时只说"好，记住了"；中英同一套长度 |
| 颜色 | 暗色座舱主题；场景色只来自光元素，用于灯带与卡片描边，文字保持中性 |
| 行驶态 | 行驶中只灯语加一句，卡片延后进收件箱；高负荷什么都不做；副驾屏可在行驶中出卡给副驾 |
| 多人 | 卡片标"当前：车主"；客人模式有横幅；身份不确定不读不写记忆 |

**5.7 工程组成。** 沿用 v6 骨架，新增四个模块：呈现管家，管预算、冷却、行驶态与形式选择；场景时间线引擎，管淡入、维持、谢幕、触发；"它的想法"收件箱与客人模式；D1 判官宿主开关。注册表与验证器已有。模型只用在闲聊答话、场景大脑一次调用、建议文案；路由、执行、时间线全部脚本化，保证演示稳定。

**5.8 评测。** E7 隐性触发 200 条中英样本，三态判对率；D1 两案在同一 200 条上的一致率、时延、上下文保真；四件套加坍缩率、注入通过率进面板；每条旅程一份 10 项体验走查表，设计评审用。

**5.9 工期 4 周。** W1 骨架与呈现管家、时间线引擎；W2 场景大脑接入，旅程一跑通，分镜与卡片视觉稿评审；W3 旅程二、三，热更新，客人模式，D1 开关；W4 打磨、指标面板、演示稿。
