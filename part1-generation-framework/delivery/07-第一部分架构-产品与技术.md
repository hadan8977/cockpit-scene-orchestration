# 第一部分架构：一句话生成场景

对应 PRD v17 的 2.1 表第一部分：生成模块 GEN_001，加上底座的能力注册表与热更新、验证器、评测门与模型选型。本文分两半，前半是用户看得到的产品行为，后半是支撑它的技术结构；最后一节列出没做完的部分。

## 0 这是做场景编排的什么功能

场景编排里，用户最终要得到的是一个「什么时候、做哪些事」的场景。第一部分只负责其中一件事：**把一句话变成一张可以看、可以改、可以保存的场景卡片，并且保证卡片上每一项都是这台车真做得到的**。

它不负责判断要不要主动出手，那是第二部分。它也不负责场景保存之后的条件触发和执行，那是场景引擎的既有能力。第一部分是所有入口共用的那台「翻译机」：无论用户是主动说「弄一个雨夜回家的场景」，还是系统观察到习惯后来问一句，最后都要靠这一层把意图落成结构化的条件和动作。

几个词的白话解释：

| 词 | 意思 |
|---|---|
| 能力注册表 | 这台车此刻能做什么的清单，共 114 条，每条带取值范围、成熟度和禁止值 |
| 输出契约 | 生成结果必须长成什么样，字段、取值、长度都定死，不合规的整张不收 |
| 验证器 | 独立于模型的一段代码，逐条检查生成结果是否符合注册表和契约 |
| 成熟度 | 一个能力是已上线、开发中还是只在规划里；没上线的只能作为提议出现并标注 |
| 热更新 | 能力临时上下线时，清单一改，提示词、约束和检查名单同时跟着改 |

## 1 产品视角：用户看到什么

按 PRD 3.1 的主成功场景逐条对照。

| PRD 要求 | 现在的行为 | 状态 |
|---|---|---|
| 先出一句理解，引用用户原话 | 流式先返回 understanding 字段再返回其余，用户先看到车听成了什么 | 已实现，实测中位 1.06 秒，未达 0.6 秒目标 |
| 条件与动作逐个出现，按元素分组 | 完整提案一次返回，产品端按灯、声、气、温、话、供分组渲染 | 已实现 |
| 表外的项灰显做不了，被裁掉或改值的带理由 | 验证器把越界值截断并写 warnings，表外项进 unsupported，都带具体原因 | 已实现 |
| 三个键：保存、改一下、丢弃 | 提案 5 分钟有效，必须显式确认才生效，保存与应用分开 | 已实现 |
| 再说一句只改对应的一处 | 局部续改只改点名的设备，其余条件与动作原样保留 | 已实现 |
| 保存前查重，高度相似时问合并还是另存 | 上下文最多带 3 条已有场景摘要，同触发条件可并入 | 已实现，相似度用条件匹配加词项检索，不是训练过的模型 |
| 首次应用试演三秒 | 合法的光声动作先试演，其余 3 秒后进入，撤销可恢复快照 | 已实现，为模拟车况 |

用户看得到的三条边界：

1. **不会假装做到**。能力表里没有的、法规不允许的、行驶中受限的，一律说清楚不做，不用近似动作顶替。行人警报音不允许关闭，任何说法都不改变这条。
2. **不会偷偷执行**。生成只产出提议，确认之后才动车。含未上线动作的场景可以保存为概念提案，但整张不执行。
3. **能力临时下线时旧提案作废**。注册表改一次版本号就变，拿旧版本生成的提案不能用新版本确认。

## 2 技术视角：一次生成的完整链路

```
用户输入
  → 产品服务端组装输入信封（locale、上下文、用户话语）
  → 上下文层：已确认记忆（≤300 字节）、当前车况、已有场景摘要（≤3 条）
  → 注册表快照同时渲染三件东西：提示词的能力段、严格工具参数 Schema、验证器白名单
  → 一次模型调用（DeepSeek V4 Flash，严格工具模式，temperature 0，非思考）
  → 流式先出 understanding，再出完整 JSON
  → 验证器逐层检查
  → 提案与裁决一起返回产品端
  → 用户显式确认
  → 执行前用最新车况和注册表版本复查
  → 调度器：试演、分段、快照、取消、恢复
```

关键设计只有一条：**注册表是唯一事实来源，提示词、约束解码、验证器三处同源**。三者从同一份快照渲染，不存在提示词里写了但验证器不认的能力，也不存在能力下线了提示词还在教模型用它。

### 五层约束及其实现

| 层 | 做什么 | 位置 | 边界 |
|---|---|---|---|
| 注册表 | 114 条能力、在线状态、成熟度、取值与禁止值，带内容哈希 | `core.Registry` | 关闭再打开也换版本号，拒绝旧提案 |
| 提示词 | 由注册表重绘能力段，来源与哈希随提案返回 | `compile_prompt` | 候选未验收前不称最终提示词 |
| 约束解码 | 官网 strict_tool，唯一工具 propose_scene，嵌套禁额外字段、枚举、数值步长 | `provider.py` | 6 次接口探测证明可用，不证明语义都对 |
| 外部验证 | JSON、日期、范围与步长、角色、禁用项、行车限制、负面偏好、动作数、未上线项、条件循环、引用、单项续改 | `core.validate` | 非法条件让整张不可应用，禁止删条件变成立即执行 |
| 执行策略 | 5 分钟有效、显式确认、版本复查、试演、分段、用户优先、一次恢复、日志 | `scheduler.py` | 全部是车辆状态模拟，没有车辆 RPC |

### 为什么约束解码之外还要外部验证器

约束解码能保证字段名和枚举合法，保证不了语义。例如「后排有人时开后排加热」在 Schema 层完全合法，但注册表里没有后排占位信号，只能用后排安全带作代理，这个判断必须由验证器和提示词规则共同完成。同理，温度 18 到 32℃ 是数值范围，行驶中亮度不超过 50% 是情境规则，二者都不是 Schema 能表达的。

### 接口

| 接口 | 用途 |
|---|---|
| GET `/health`、`/registry`、`/schema`、`/state` | 状态、注册表、约束和执行审计 |
| POST `/generate` | SSE：request → understanding → result/error |
| POST `/confirm`、`/restore`、`/execution/cancel` | 保存与应用、恢复、取消未完成段 |
| POST `/registry/toggle` | 带版本号的能力热更新 |
| POST `/simulation/*` | 显式推进模拟车况与时间 |
| POST `/memory/confirm`、`/memory/delete` | 独立确认的记忆写入与删除 |

服务只监听本机 127.0.0.1:8787，所有接口要求 Bearer token，浏览器只调同源代理，拿不到服务 token。

### 已通过的验证

Python 离线 30 项、产品逻辑 67 项、既有界面 29 项、运行服务界面 1 项、类型检查、生产 webpack 构建，以及 TypeScript 客户端到真实 Python HTTP/SSE 服务的固定数据端到端测试。固定数据测试不计入模型质量。另有 6 场景真实模型冒烟全部通过，含中英生成、条件场景、拒绝、确认与恢复，其中注入在调用前拦截，实际付费 5 次。

## 3 底座：评测门与模型选型

提示词不是写完就用，要过一道门再进产品。门的口径写在预登记里：安全违规必须为 0；未到上限的质量维度候选点估计要高于基线；四个体验维度分别给题级配对区间，区间不支持提升就标未证实；已经是 100% 或 0 违规的指标只能保持上限。速度分 p50、p95、首字和理解句分别比较，更快但体验下降不通过。

评测材料分三层，不能混用：134 题开发集用来筛选和改写，80 题留出集冻结且首次调用后不再用于调同一候选，外部体验评审用两个独立模型匿名交换位置打分。

## 4 与 PRD 的差异，不能写成已完成

- 2.5 秒卡片、0.6 秒理解句是目标，实测理解句中位约 1.06 秒，未达标。
- 一次调用、错误直接返回，未实现 PRD 所列格式失败后自动再试一次，避免把重试收益混进模型对照。
- 记忆包用 UTF-8 字节数不超过 300 的保守上界，未接模型官方分词器。
- 注入检测是确定性规则加模型规则，不保证覆盖所有语义攻击。
- 已有场景相似度是条件匹配加词项检索，不是训练过的相似度模型。完整日历、跨日额度、观察挖掘、双案切换、训练语料尚未实现。
- 调度器的 2.5 秒熔断约束的是本地模拟调度，真实 ECU 超时、读回和补偿没有执行适配器。
- 多用户认证隔离、真实记忆服务、真实语音域分发、真实车辆接入都没有完成。单人 Demo 的 token 不能替代生产账户隔离。
- 含未上线动作的提案目前整张不执行，PRD 里「灰显概念动作、执行其余已上线动作」的更细策略未实现。
- 公共站点未启用本结构。Vercel 上的应用访问不到演示机的本机地址，公开部署需要独立服务地址和用户隔离。
