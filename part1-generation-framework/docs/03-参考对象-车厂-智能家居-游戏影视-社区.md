## 3. 从参考对象提炼的规律，以及本项目怎么用

1. **编辑器不是主路径**。奔驰把模板和 AI 学习列为三分之二的创建方式；Google 把 AI 生成放在脚本编辑器这条专家路径里。本项目：四条输入路径，一句话与主动建议为主，编辑器保留给极客。
2. **主动要克制**。Alexa 的建议被大量用户搜索怎么关掉。本项目：主动程度三档，每天最多一条建议，只在上车后或停车后提，行驶中不提。
3. **分享要有承载物和参数化**。理想是海报加扫码，Home Assistant 是带参数的蓝图。本项目：场景分享时把“家”“公司”“家人”参数化，安装时重新绑定。
4. **为别人创建场景**。蔚来“副驾上车时打开按摩并说加班辛苦了”把场景从“控制”变成“关心”。本项目：storyboard S7。
5. **口令**。蔚来的专属口令把复杂场景压缩成一个词。本项目：场景名即口令，创建时由模型起名，用户可改。
6. **学习阈值要适配车的节奏**。奔驰用 8 次；车一天只有两次通勤，8 次要一周。本项目：3 次同条件重复加一次询问 [设计选择，需要 A/B]。
7. **找不到等于没有**。奔驰用户在论坛问“Routines 在哪”。本项目：场景入口放在语音和上车卡片，而非设置菜单深处。

## 4. 游戏与影视：为什么它们的“自动化”让人喜欢

### 4.1 游戏

**《最终幻想 XII》的 Gambit 系统**是最直接的参考。玩家给队友设置按优先级排列的“条件 → 行动”规则，例如“队友 HP 低于 50% → 治疗”“敌人怕火 → 火系魔法”。它让大量非程序员玩家主动去“编程”，原因有五条，每条都能映射到场景编排：

| Gambit 的做法 | 为什么有效 | 本项目对应 |
|---|---|---|
| 条件是语义化的（“队友 HP 低于 50%”），不是原始数值 | 玩家用自己的话思考 | L1 派生语义（工作日、回家、暴晒后） |
| 规则触发时在战斗里看得见 | 看见才能学、才能调 | 触发时说一句或显示卡片 |
| 规则按优先级从上到下，只有一条生效 | 冲突处理简单可预期 | 场景 priority 字段，冲突时高优先级生效 |
| 条件词是逐步获得的，不是一开始全给 | 渐进披露，不吓人 | 第一版只开放七个时刻，随使用解锁更多条件 |
| 设完马上能在战斗里验证 | 即时反馈 | 创建后立即“试运行一次”，看车会做什么 |

其他游戏：

- 《模拟人生》的“自由意志”滑杆和需求模型：人物按自己的需求行动，玩家随时可以接管。对应“主动程度”档位，以及把电量、空气、温度当作车的“需求”。
- 《动物森友会》：真实日历、季节、节日、生日；村民记得你做过的事并在对话里提起。对应日历感知的内容与“它记得”的时刻。
- 《旅行青蛙》和电子宠物：你不在的时候它做了什么，回来给你看。对应“离车报告”：预热完成、下雨关窗、哨兵事件。
- 《极限竞速 地平线》的电台主持人会评论你的进展。对应车在停车或低负荷时的一两句旁白，行驶中不做。
- 《死亡搁浅》的“点赞”：别人用了你造的桥会给你点赞。对应场景分享的轻量反馈（“有 1200 位车主装了你的场景”）。

### 4.2 影视与小说

| 角色 | 让人喜欢或害怕的原因 | 本项目的取舍 |
|---|---|---|
| KITT（《霹雳游侠》） | 有声音、有忠诚、开口的时机对，会拒绝危险指令 | 场景经由语音助手人格出口；安全类拒绝要有礼貌的说法 |
| JARVIS（《钢铁侠》） | 短命令换来多步执行，简短确认，会提出异议 | 一句话建场景；触发时一句确认；撤销率高时提出“要不要改成建议” |
| TARS（《星际穿越》） | 幽默 75%、诚实 90%，人格可调 | 主动程度、话多话少、称呼方式做成可调项 |
| Samantha（《她》） | 记忆与连续性带来的亲密感；风险是过度依赖 | 记忆做“它记得我上次冷”，不做情感陪伴的承诺 |
| 大白（《超能陆战队》） | 以人的状态为目标，不以任务完成为目标 | 场景的成功标准是“用户没有撤销”，不是“动作执行了” |
| HAL 9000、奥创 | 不可覆盖的自动化 | 任何场景都能一句话停掉；行驶中不做 B、C 类动作 |
| MOSS（《流浪地球 2》） | 全知但冷，给人威胁感 | 记忆和推断要让用户看得到、删得掉 |
| 哆啦 A 梦 | 在合适的时刻拿出合适的道具 | 场景的本质：对的时刻、对的几个动作 |
| 《星际迷航》的舰载电脑 | 直接命令又快又准，没有人格 | 直接命令走快路径，不加旁白 |
| 阿西莫夫机器人三定律 | 安全优先于服从 | 安全类场景优先级永远高于用户场景 |

### 4.3 被喜欢的自动化的七个特征

1. 有名字、有声音。
2. 开口有时机，不在我忙的时候说话。
3. 做了什么让我看得见。
4. 我随时能否决，否决一次它就记住。
5. 它记得我，尤其记得我上次的不满。
6. 它和日历、季节、天气一起活着。
7. 我能把它调成我喜欢的样子。

## 5. 社区与生态运营

前提三条，缺一条就会变成没人逛的画廊 [推断，可用智能家居社区里自动化分享的活跃度来验证]：

- 可移植：场景里的私有语义参数化。
- 安全审核：只允许 A 类动作的场景自由分享；含 B 类动作的场景要审核。
- 上下文推荐：在对的时刻推对的场景（“秋天了，很多车主开了雾天模式”），不能只靠用户去逛。

分层运营，从便宜的开始：

| 层 | 内容 | 谁做 | 频率 | 成本 |
|---|---|---|---|---|
| 官方季节包 | 春节回家、五一自驾、开学接送、梅雨、暴晒、雾天、露营 | 产品团队 | 季更 | 低，先做 4 个 |
| 达人包 | 露营达人的“露营模式”、宝妈的“哄睡模式”、宠物主的“带狗出门” | 合作创作者 | 月更 | 中 |
| 车友分享 | 海报、口令、一键安装 | 用户 | 持续 | 审核成本 |
| 车队与活动场景 | 车友会自驾时灯光与音乐同步、活动签到场景 | 运营 | 按活动 | 中 |

排序信号用使用人数、7 日存活率、撤销率，不用点赞数。先做官方季节包，看安装率再决定是否扩到达人和车友层。
