弱意图场景编排·精简版（源 v13 PRD）
1. 产品概述
1.1 产品背景
座舱语音今天的三条路径都不接「状态类需求」：强意图指令（「打开空调」）走车控秒级执行；用户只说状态或情绪（「我好累」「今天热死了」）落进闲聊，只换回一句共情；想生成场景必须明说「帮我弄一个xx场景」，且入口锁在编排页面里。共同前提是用户自己知道要什么、并且说出来——大多数时刻用户说不出，或者压根没意识到自己在重复同一串操作。
能力侧已经齐了：场景大脑（编排 PRD IFT_AI_002）已能把「车里有点闷」这类模糊需求生成「触发项＋执行项」；场景引擎负责编排与执行；小塔记忆 PRD 已规划用车偏好与操作行为记忆。缺的是中间一层判断：什么时候该主动出手、以什么形式出手、出手的分寸边界在哪。本方案就是在既有场景编排之上补这层「主动层」：五个入口进来，一道门控判断，六种形式出去，信任逐级上升，分寸全局记账。
1.2 产品价值及体验目标
看用户：多任务组合传统模式 8-10 次交互，场景化后 1-3 次，本方案再省掉「先想到、再说出、再配置」三次隐性成本。体验目标三句话：它懂我但不烦我；它居然记得；一切我说了算。
看企业：行为记忆加场景资产构成粘性，越懂你换车成本越高；运营从「云端推模板」升级为「替用户生长场景」。
看行业：各家主动能力都停在「单动作级建议」，没人把主动和可编排的组合能力接通——这是有场景引擎的玩家独有的位置。奔驰用约 8 次重复才敢生成例程、宝马忽略即停、Nest 因不可见的自动化被用户整个关掉，三条教训分别落成本方案的：高学习门槛、忽略要计费、学习成果全透明。
1.3 名词解析
| 词 | 定义 |
|---|---|
| 场景编排 | 已有功能：用户把一组车控动作打包成「场景」，条件满足时一起执行 |
| 场景大脑 | 已有组件（编排 PRD IFT_AI_002 / 大模型 PRD 3.8）：把一句话生成「触发项＋执行项」的大模型服务 |
| 场景引擎 | 已有组件：场景的编排界面与执行通道 |
| 强意图 / 弱意图 | 本文口径：强意图＝明确动作指令（「打开空调」）；弱意图＝只说状态或情绪、没说要干什么（「我好累」）。注意与语音 PRD 全时免唤醒的「强/弱意图指令」（VR_BA_034）不是同一概念 |
| 门控 | 所有主动出手的唯一判断通道：问零显著性（仅观察入口）＋三问（能不能做、此刻合不合适、值不值得） |
| 建议对象 | 门控与呈现之间的标准数据结构：来源、类型、风险级、价值分、允许形式、信任级、撤销动作、解释一句 |
| 信任阶梯 | 同一场景的主动程度分五级 L0-L4，用得越久越自动，出问题随时降级 |
| 分寸预算 | 整车共享的主动打扰限额账本 |
| 负面记忆 | 用户拒绝、撤销、总是关掉的行为沉淀为一票否决项 |
| 影子模式 | 候选场景先只记录不执行，与用户实际行为对照，达标才获得呈现资格 |
| 反向学习 | 学习「用户总是关掉什么」，生成负规则 |

2.2 整体功能与架构
[图 1]
数据流：五入口 → 门控 → 场景大脑 → 呈现调度 → 场景引擎 → 反馈。三条原则：入口多、判断单点（同一句话只判断一次）；生成复用、执行复用（不新建生成器和执行器，场景大脑加一个意图分支，执行全走场景引擎）；状态与表现分离（场景大脑只发状态，助手形象是唯一化身）。

3.2 弱意图语音旁路 ENTRY_001
| 项 | 内容 |
|---|---|
| 业务功能 | 闲聊照常答话，门控异步判断要不要出场景建议 |
| 前置条件 | 用户已登录授权账号；功能总开关开启 |
| 触发条件 | query 落域闲聊，且语义含可服务化的状态或情绪表达 |
| 主成功场景 | 1. 闲聊正常共情回复，时延与话术完全不变；2. 门控异步跑三问，不过则到此结束，用户无感知；3. 通过则生成建议对象，按信任级呈现（首遇一句话询问）；4. 用户回应「好」，出场景卡片或先试演三秒 |
| 扩展场景 | 连续对话中门控判定语境未结束，本轮不呈现；副驾音区说话，建议默认只作用于副驾区域并注明对象 |
| 异常情况 | 门控超时本轮放弃，宁可不建议不可拖慢对话；生成服务异常静默吞掉，闲聊不受影响 |

3.3 门控 GATE_001
[图 2]
| 项 | 内容 |
|---|---|
| 业务功能 | 所有主动出手的唯一判断通道 |
| 主成功场景 | 问零（仅观察入口）：模式 3 次以上、条件元组稳定、涉及 2 个以上元素才算候选。问一：有没有车能接的状态或目标。问二：此刻合不合适——行驶负荷、分寸余额、冷却期、异常日。问三：值不值得——相关度，命中负面记忆直接沉默 |
| 判空优先级 | 负面记忆＞分寸预算＞异常日＞三问；任何一条否决即沉默，不进任何队列 |
| 异常情况 | 判断层不可用时全部入口退回纯被动模式：宁可整个主动层静默，不可无判断出手 |

弱意图的判断宿主（对话侧还是场景大脑侧）列为开放决策点 D1，demo 两案对比后定。
3.4 信任阶梯 TRUST_001
[图 3]
| 级 | 形式 | 进入条件 |
|---|---|---|
| L0 | 静默学习，不呈现 | 默认，前 14 天 |
| L1 | 顺手提示或一句话询问 | 显著性通过，首次建议 |
| L2 | 卡片（仅停车或副驾屏，否则进收件箱） | 用户对 L1 说了「好」 |
| L3 | 计时器确认（15 秒不取消即执行，方控可应答） | 已确认 3 次且无撤销 |
| L4 | 静默执行加事后一句，可撤销 | L3 稳定两周 |

降级规则：撤销或「不用」降一级；两次忽略停 30 天；三次拒绝进长期负面记忆；高风险动作（C 级）永不自动，写死在验证器。一键恢复贯穿 L2 起：每次执行前拍状态快照，事后一句「还原」即回到执行前。

| 项 | 上限 |

| 一句话询问 | 每天 1 次 |
| 卡片 | 每周 2 张（含收件箱推送） |
| 同类被拒 | 7 天不提；三次拒绝进负面记忆 |
| 情绪类（纪念日、悲伤、争吵） | 从不主动，只接显式请求 |

预算账户：本地主动建议、云端运营推送、生态活动通知共用同一账户——用户感知里没有区别，账户分开等于限额翻倍。
3.6 观察入口 OBS_001
[图 4]
| 项 | 内容 |
|---|---|
| 业务功能 | 从用户行为中统计挖掘习惯，生成场景候选 |
| 前置条件 | 学习总开关开启（默认开，可关） |
| 触发条件 | 候选通过问零显著性检验，且影子模式重合度达标 |
| 主成功场景 | 1. 车端空闲时统计挖掘，每次手动操作记为「条件元组＋动作集合」；2. 同一动作集合在同一条件下 14 天内出现 3 次以上、一致率七成、动作 2 个以上成为候选；3. 候选入影子模式，只记不执行，对照实际行为最多 7 天；4. 达标后获得呈现资格，以顺手提示起步（「这周第 4 次这样调，存成『到家』场景？」），一键存为个人场景进入信任阶梯 |
| 扩展场景 | 影子模式不达标的候选静默丢弃；反向学习生成的负规则进「它学会了什么」页，可删可关 |
| 异常情况 | 挖掘只在车端空闲时跑，中断不影响下次；舱内感知信号缺失时只用手动操作与状态两类信号 |

信号三类：手动操作序列（灯、温、座椅、音乐、车窗）、车辆与环境状态（位置、时段、天气、乘员构成）、舱内感知（只用事件不存画面）。
3.7 呈现形式 FORM_001
| 形式 | 什么时候 | 规则 |
|---|---|---|
| 顺手提示 | 用户正在操作的面板上 | 一行字，一键，不遮挡操作 |
| 一句话询问 | 停车或低负荷行驶，首次建议 | 15 字内 |
| 计时器确认 | 已确认过的场景再触发 | 通知加 15 秒倒计时，方控可应答 |
| 试演三秒 | 显式创建与同意后的首次应用 | 只动灯与声，先看效果再决定 |
| 静默执行加事后一句 | L4 场景 | 事后一句可撤销，撤销即降级 |
| 一句话改一处 | 场景进行中 | 只动一个元素，改了就记 |

卡片只保留两处：停车时的显式创建结果与收件箱。
3.8 冲突仲裁
语音车控＞场景自动执行＞主动建议。 场景引擎是所有原子动作的单点执行通道；执行中有新建议则转收件箱，不插队；闲聊答话完整结束再出建议，两句声音永不同时出现。

[图 5]
| 阶段 | 内容 |
|---|---|
| 出生 | 默认 L0/L1，带来源标记（语音创建/观察学习/模板改） |

| 传承 | 场景随账号走：换车带走，家庭账号共享、各自微调 |

3.10 异常情况处理
判断层不可用：全部入口退回纯被动，宁可静默不可乱出手。
生成服务异常：弱意图路径静默吞掉；观察路径候选丢弃，下轮重出。
执行异常：运行前快照兜底一键恢复；异常率高的场景类型冻结信任爬坡。
注入与越权：闭集约束解码、表外能力返回不支持、注入统一拒绝，全部写在验证器不写进 prompt。
3.11 生成与安全基线
[图 6]
生成框架不依赖存量系统改造：能力注册表、prompt 与约束、外置验证器、评测集，四样凑齐就能跑。注册表是生成与安全共用的同一份事实（生成侧约束解码、执行侧白名单）；安全约束全部写进验证器不靠模型自觉——结构校验、能力白名单、安全禁动作清单、超时熔断（2.5 秒降级）、呈现预算、注入双保险、全链路日志。模型选型体验盲评先行，话术生硬的指标再高也降档。
4. demo：体验验证
demo 验证三件事：边界正确（同一句话各走各路，路由过程看得见）、有分寸（门控、冷却、预算都在工作，被理解但不被打扰）、建议由记忆驱动（两个人说同一句话得到不同建议）。
4.1 旅程一：一个傍晚（弱意图主线）
| 用户做什么 | 系统做什么 | 用户感受 |
|---|---|---|
| 傍晚下班上车，「今天热死了」 | 闲聊秒级共情；门控通过，助手多问一句「要不要开个凉快点的模式？」 | 被接住，没被打断 |

4.4 评测与节奏
评测：200 条中英样本的触发准确率；四件套＋坍缩率（模糊意图被硬编成具体动作的比例，越低越好）＋注入通过率，全程实时可视化；D1 双案同评测集对比上下文保真与时序。
节奏 6 周：选型与骨架 → 场景大脑接入、例句跑通 → 门控、记忆、双案 → 三旅程打磨、指标面板 → 真实接口对接准备 → 总结与演示。
5. 横向支撑能力及对外依赖
与场景编排（IFT）：复用编排界面、我的场景、场景引擎；显式入口放开＝IFT_AI_002 已有句式的入口范围扩大；执行异常处理以场景引擎 PRD 为准。
与大模型（LLM）：场景大脑加一个意图分支（显式/弱意图/观察共用契约），新增记忆读接口一根线，其余全复用。
与语音（VR）：强弱意图路由判据落在语义理解层（VR_BA_015）；弱意图旁路对答话链路零改动；语音车控永远优先。
与小塔记忆：操作行为记忆提取是观察入口的数据底座；负面记忆作为新增记忆类型；记忆检索复用其检索接口。
与账号/隐私：场景随账号、双端同步、家庭共享；观察信号车端处理，感知只用事件不存画面，学习成果全透明可删。
性能：弱意图旁路对对话零感知（门控超时就放弃）；判断到呈现 3 秒内；确认响应 1 秒内；观察挖掘只在车端空闲时跑。
