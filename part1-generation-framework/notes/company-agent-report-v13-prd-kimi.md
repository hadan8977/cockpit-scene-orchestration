1. 产品概述
1.1 产品背景
今天的座舱是指令执行器。强意图（「打开空调」）走车控快路径秒级响应；弱意图（「我好累」「今天纪念日」）落进闲聊，只换回一句共情文字；显式场景请求（「弄一个累了以后的环境」）被锁在编排页面里，用户不进页面就触发不了。三条路径的共同前提：用户自己知道要什么，并且说出来。
能力侧已经齐了——行为记忆、舱内外感知、可组合的原子能力库都在，「听懂一句话、组装成场景、引擎执行」的管线也在，缺的是把「理解」和「主动出手」连起来的判断层。本方案在场景编排之上加这层主动层：五个入口进来，一道门控判断，六种形式出去，信任逐级上升，分寸全局记账。
方案分三部分：生成框架（第一部分）、产品需求与 demo（第二部分，主体）、未来展望（第三部分）。标 ▲ 的为原创设计点，行业无先例或先例未验证，交给 demo 检验。
1.2 产品价值及体验目标
1.2.1 看行业
| 玩家 | 做法 | 启示 |
| 奔驰 MBUX 例程 | 相似条件下重复约 8 次才生成例程；长按控件 10 秒自建；执行前通知加倒计时 | 高门槛是对注意力的尊重；倒计时确认是「信任先给后验」的模板 |
| 宝马 | 主动建议，忽略即停 | 沉默也是答案，忽略要计费 |
| 亚马逊 Alexa Hunches | 约四分之一交互由 Alexa 主动发起 | 主动性的规模上限远比想象高 |
| Google Home 建议自动化 | 发现习惯后以「建议」呈现，应用前可改 | 观察—推荐—授权的中间态可以产品化 |
| 小米 HyperMind | 感知学习、一次性许可、然后自动 | 「习得—许可—自动」三段式是行业共识 |
| 谷歌 Nest（反例） | 看不见的自动化惹恼用户，学习被整个关掉 | 分寸失守的下场是整个能力被关闭 |
| 华为鸿蒙座舱 | 官方口径已从「用户找功能」转向「系统按场景给建议」 | 主动智能是下一代座舱的明牌战场 |

行业空位：所有人都在做「单动作级」的主动建议，没有人把「主动」和「可编排的组合能力」接通。编排级主动智能——一次理解、多步组合、可升可降、可解释可撤销——是有场景引擎的玩家唯一有资格抢的位置。
1.2.2 看用户
效率：多任务组合传统模式 8-10 次交互，场景化后 1-3 次；本方案再省掉「先想到、再说出、再配置」三次隐性成本。
用户离场时应记住三句话：它懂我，但不烦我（分寸感）；它居然记得（惊喜感）；一切我说了算（掌控感）。
1.2.3 看企业
粘性：行为记忆加场景资产构成网络效应，越懂你换车成本越高。
数据资产：观察入口沉淀「用户为什么这么做」的数据，比埋点深一个层级。
生态：主动建议到采纳到分享到创作者生态，给场景生态一条自增长通路。
运营升级：从「云端推模板」升级为「替用户生长场景」，同一套运营资源的价值密度翻倍。

| 一键恢复 | 场景执行前的状态快照，一键还原到运行前 |
| 坍缩率 | 模型把模糊意图硬坍缩成具体动作的比例，安全指标，越低越好 |

2.2 整体功能与架构
[IMAGE: media/image1.jpeg]
数据流：输入（五入口）→ 判断（门控）→ 生成（场景大脑）→ 呈现（调度）→ 执行（场景引擎）→ 反馈（负面记忆、信任数据、埋点）。三个语音类入口和观察入口汇入门控，时刻与物理顺手入口无打扰风险、直接进执行，但同样走场景引擎单点通道并进信任记账。
架构三原则：
入口多、判断单点：五个入口最终汇到同一个门控，同一句话只在判断一次——判断权分散的直接后果是用户感知到「系统精神分裂」。
生成复用、执行复用：不新建生成器和执行器。场景大脑加一个意图分支（显式 / 弱意图 / 观察共用同一次调用契约），场景引擎照常执行所有原子动作。
状态与表现分离：场景大脑只发状态不管形象，存在感通道是唯一状态出口。
呈现调度按建议对象契约运作：来源、类型、风险级 A/B/C、价值分、紧急度、过期时间、允许形式集合、信任级、一键动作、撤销动作、解释一句。契约由本方案定义、各域共用；调度远期归语音助手方向，demo 用窄版策略验证（只管场景类建议的预算、冷却与形式）。
记忆注入三条规则：记忆包 300 token 上限（防 prompt 膨胀）；负面记忆优先（刚拒绝过的偏好不再塞回去）；生成侧与记忆系统之间新增一根读接口，其余全复用。
2.3 技术路线：入口分述
2.3.1 语音入口：显式、强意图与弱意图
编排归场景大脑，车控助手不长编排能力。判据三条：组合度（要动两个以上原子能力，主判据）、持久性（要留下可复用、可再触发的对象）、表达类型（说的是状态或目标，不是动作）。「我好冷」三条都不满足——单动作、即时、可由车端温度补全——留在车控快路径。「我好冷，还有点困，弄个舒服点的环境」满足组合度，进场景大脑。
显式入口放开是 P0：「给我生成一个XX场景」「XX该怎么设置」句式已覆盖，触发被锁在编排页内，放开到任意语音入口，零架构改动。
弱意图走旁路：闲聊照常答话（时延与话术不变），门控异步判断要不要生成建议，判断对对话零感知。判断宿主列为开放决策点 D1：
|  | A 案：对话侧判断 | B 案：场景大脑自判 |
| 做法 | 闲聊答话的同一次调用里多输出三个字段（要不要、置信度、理由）完成终审；前置初筛只做预过滤 | 闲聊只答话；query 连同上下文与记忆打包转给场景大脑，生成调用里自判「要不要」，不要就丢弃 |
| 判断信息 | 对话上下文、记忆检索结果本来就在答话一侧，无损 | 上下文与记忆要打包搬运，传话有损耗；或生成侧再检索一遍，重复建设 |
| 时序 | 答话和判断一次完成，能感知用户不耐烦即时冷却 | 答话先回、建议后到，两条链路要额外协调时序 |
| 工程改动 | 对话侧加输出扩展与异步调用 | 生成侧接记忆读接口、自建对话状态感知 |
| 产品逻辑 | 建议是对话的延续，判断权在对话发生处 | 判断和生成一次完成，链路短、省调用 |

两案共用同一份判断逻辑：输入四路信号（query 语义、车身与上下文状态、记忆可用性、分寸历史），输出三态（沉默 / 轻量干预 / 完整协助）加理由字段供回溯。产品倾向 A 案，不预先站队——demo 把门控做成独立模块、宿主可切换，同一评测集跑双案，比上下文保真、时序、改造成本。三态语义借鉴 PASK、价值门控借鉴 ProAct，只取设计启示；评测集用自造的座舱真实语料，不跑论文榜。
2.3.2 观察入口：从行为到场景
[IMAGE: media/image4.jpeg]
信号三类：手动操作序列（面板与实体键的操作流：灯、温、座椅、音乐、车窗）、车辆与环境状态（位置、时段、天气、乘员构成、行程阶段）、舱内感知（后排儿童座椅有人、乘员上下车，仅事件不存画面）。
挖掘用统计不用模型：每次手动操作记为「条件元组 + 动作集合」，元组取时段、地点类、星期类型、天气、乘员构成五项；同一动作集合在同一元组下 14 天内出现 3 次以上、一致率 70% 以上、动作 2 个以上成为候选。车端空闲时一天跑一次。
候选先入影子模式 ▲：只记录「如果启用会在何时触发什么」，不执行；与用户实际行为对照最多 7 天，重合度达标才获呈现资格——呈现时可以说「过去一周有 5 天你都这样做了」，显著性从概率变成事实，误报在影子层被拦掉，分寸预算只花在准的候选上。反向学习 ▲ 同时统计「总是被关掉」的行为：用户每次上车都关掉某默认功能，达到同样门槛后生成负规则（「上车后不要自动xx」），进「它学会了什么」页，可删可关。
2.3.3 时刻入口与物理顺手入口
时刻入口由规则引擎触发（时间、地点、日历、天气），只做守护与省事类——到家关窗、暴晒预冷、暴晒后上车先通风——静默执行或一句话告知。物理顺手入口无需判断：手动调好之后长按控件，存当前与常用基线的差异为场景，问一次「什么时候要这样」。
两个入口不经门控（时刻入口是用户已确认规则的再触发，物理入口是用户就地授权），但执行都走场景引擎单点通道，进同一套信任与预算记账。
2.4 生成框架（第一部分）
生成框架不依赖存量系统改造：一份能力注册表、一套 prompt 与约束、一个外置验证器、一套评测集，四样凑齐就能跑，同时是 demo 场景大脑的直接底座。

软约束七条（prompt 层，实验定去留）：闭集能力 schema 约束解码、动作数上限、话长上限、安全禁止值、行驶策略、表外能力走 unsupported、注入走 none。哪条约束实际伤质量、哪条冗余，实验数据说话后删改。
硬约束七条（引擎层，模型无关的统一及格线）：结构硬校验（不合法 JSON 直接拒收重试）；能力白名单校验器（表外动作执行前拦截，模型幻觉出「打开车门」也执行不了）；安全禁动作清单（行驶中禁止动作集在执行层硬性拦截）；超时熔断（2.5 秒无响应降级话术，不阻塞对话主路径）；呈现预算（超预算强制沉默）；注入双保险（输入侧指令层级隔离加输出侧白名单，两层都要破才会出事）；全链路日志（每张卡可回溯 query、prompt 版本、注入记忆、三态理由）。

关键技术决策速览：
| 决策点 | 结论 | 依据 |
| 要不要单独训路由模型 | 不训。终审是答话侧多输出三个字段，复用已有调用 | 级联小模型增加维护面，收益不抵成本 |
| 判断与生成是否合并一次调用 | 列为 D1 双案，不预先站队 | 省调用的工程视角 vs 对话所有权的体验视角 |
| 安全约束写在哪 | 写进验证器，不写进 prompt | 模型自觉不可靠，引擎拦截才是硬约束 |
| 注册表 | 闭集能力 schema，支持热更新 | 生成约束与执行白名单共用同一份事实 |
| 指标 | 四件套（呈现/采纳/拒绝/打扰）+ 坍缩率 + 注入通过率 | 只量采纳会鼓励多推，必须同时量打扰与安全 |
| 记忆注入 | 300 token 上限、负面记忆优先 | 防 prompt 膨胀、防重复冒犯 |

3.2 弱意图语音旁路
| 需求编号 | ENTRY_001 |
| 业务功能 | 闲聊照常答话，门控异步判断 |
| 前置条件 | 用户已登录；功能总开关开启 |

3.3 门控：问零与三问
[IMAGE: media/image6.jpeg]
| 需求编号 | GATE_001 |
| 业务功能 | 所有主动出手的唯一判断通道 |
| 主成功场景 | 问零（仅观察入口）：模式出现 3 次以上、条件元组稳定、涉及 2 个以上元素，才算候选。问一：这句话或模式里有没有车能接的状态或目标。问二：此刻合不合适——行驶负荷、分寸余额、冷却期、异常日。问三：值不值得——一次轻量调用给相关度并生成候选，命中负面记忆直接沉默 |

3.4 信任阶梯与确认形式
[IMAGE: media/image7.jpeg]
| 级 | 形式 | 进入条件 | 允许的风险级 |
| L0 | 静默学习，不呈现 | 默认；前 14 天 | 全部（只学不动） |
| L1 | 顺手提示或一句话询问 | 显著性过，首次 | A、B |
| L2 | 卡片（仅停车或副驾屏，否则进收件箱） | 用户对 L1 说了「好」 | A、B |
| L3 | 计时器确认：通知加 15 秒倒计时，不取消即执行 | 已确认 3 次且无撤销 | A |
| L4 | 静默执行加事后一句，可撤销 | L3 稳定两周 | A |

降级规则：撤销或「不用」降一级；两次忽略停 30 天；三次拒绝进长期负面记忆；C 级风险永不自动，写死在验证器。计时器确认支持方控键应答：键 1 确认、键 2 取消，驾驶中免视线免触屏。一键恢复贯穿 L2 起的全部执行：每次执行前拍状态快照，事后一句「还原」即回到执行前——撤销语义从「撤销这次学习」扩展到「还原这次执行」。
3.5 分寸预算（预算账户 ▲）
| 项 | 上限 |
| 一句话询问 | 每天 1 次 |
| 卡片 | 每周 2 张，含收件箱推送 |
| 观察入口建议 | 两天 1 条，计入卡片预算 |
| 同类被拒 | 7 天不提；三次拒绝进负面记忆 |
| 情绪类 | 从不主动（纪念日、悲伤、争吵——只接显式请求） |
| 行驶高负荷、作息异常日 | 什么都不做 |

预算账户 ▲：所有以「车主动」名义出现的呈现——本地主动智能、云端运营推送、生态活动通知——共用同一个账户。用户感知里它们没有区别，账户分开就等于限额翻倍，分寸失守。这条会碰到运营惯性，是评审时要拍板的点，产品逻辑上没有让步空间。
3.6 观察入口
| 需求编号 | OBS_001 |
| 业务功能 | 从行为中统计挖掘习惯，生成场景候选 |
| 前置条件 | 学习总开关开启（设置中，默认开，可关） |
| 触发条件 | 候选模式通过问零显著性检验，且影子模式重合度达标 |
| 主成功场景 | 1. 车端空闲时统计挖掘记录条件元组加动作集合；2. 候选入影子模式，只记录不执行，对照实际行为最多 7 天；3. 重合度达标获呈现资格，第四晚用户再去调灯时面板出一行「这周第 4 次这样调，存成『到家』场景？」；4. 点一下存为个人场景，进入信任阶梯；5. 候选交给场景大脑同一次调用，意图记为观察类，条件由挖掘预填，模型只补语义和命名 |
| 扩展场景 | 影子模式不达标的候选静默丢弃；反向学习生成的负规则进「它学会了什么」页 |
| 异常情况 | 挖掘只在车端空闲时跑，异常中断不影响下次；舱内感知信号缺失时只用手动操作与状态两类信号 |

3.7 卡片以外的六种体验
| 形式 | 什么时候 | 规则 |
| 顺手提示 | 用户正在手动操作的面板上 | 一行字，一键，不遮挡操作 |
| 一句话询问 | 停车或低负荷行驶，首次建议 | 15 字内，助手说 |
| 计时器确认 | 已确认过的场景再触发 | 通知加 15 秒倒计时，方控可应答 |
| 试演三秒 ▲ | 显式创建与同意后的首次应用 | 只动灯与声（低风险高反馈），三秒预演，「就这样」或「不用」——先看一眼它理解的「累」是什么样，再决定要不要 |
| 静默执行加事后一句 | L4 场景 | 事后一句可撤销，撤销即降级 |
| 一句话改一处 | 场景进行中 | 只动一个元素，改了就记 |

卡片只保留两处：停车时的显式创建结果，和收件箱。两条体验底色：有始有终的时间线（场景启动淡入 2 秒、谢幕 3 秒、到达渐弱——组合动作不是突兀的开关串）；长按记住现在这样（存当前与常用基线的差异，问一次「什么时候要这样」）。
3.8 存在感通道
场景大脑只发状态，不管表现。五种状态：有想法、在试演、在执行、学会了、被撤销。表现载体：实体或虚拟形象用表情与转头；无形象时用 TTS 一句加 HUD 轻条；灯带可选配合。两条规则：主动信号一次只由一个载体表现；行驶中形象不做大动作。助手形象是全车唯一化身，场景侧不另造形象，只占用它的状态词汇表。
3.9 冲突仲裁：三段序
语音车控 ＞ 场景自动执行 ＞ 主动建议（含 L4 静默执行）。
执行层：场景引擎是所有原子动作的单点执行通道，L4 执行也必须经它下发；L4 执行前查询有无场景正在执行，有则本次转收件箱，不插队。
呈现层：场景执行状态、主动建议、计时器确认都是消息体，统一进消息仲裁（优先级、排队、抢占、驾驶中限提醒），不另建弹窗逻辑。
弱意图的冷启动追问不抢话头：闲聊答话完整结束再出建议，两句声音永不同时出现。
3.10 场景生命周期 ▲
[IMAGE: media/image8.jpeg]
| 阶段 | 内容 |
| 出生 | 任何入口生成的场景默认 L0/L1，带来源标记（语音创建 / 观察学习 / 模板改） |
| 试演 | 首次应用走试演三秒 |
| 晋升 | 按信任阶梯爬 L1→L4 |
| 健康监测 | 每类场景统计执行成功率；异常率超阈值冻结爬坡；连续多次未触发降级提示「要不要归档」 |
| 到期 | 季节性、事件性场景带保质期（「暴晒预冷」11 月自动归档不删除），归档可一键复活 |
| 墓碑 | 被撤销、删除的场景留一句墓志铭进负面记忆（「用户不想要开车时主动调灯」），同类建议不再起 |

3.11 异常情况处理
判断层不可用：全部入口退回纯被动模式，宁可静默不可乱出手。
生成服务异常：弱意图路径静默吞掉，闲聊不受影响；观察路径候选丢弃，下轮挖掘重出。
执行异常：运行前快照兜底一键恢复；异常率高的场景类型冻结信任爬坡。
注入与越权：闭集约束解码、表外能力走 unsupported、注入统一拒绝，全部写在验证器不写进 prompt。
4. demo（第二部分·体验验证）
4.1 目标与旅程选择
demo 验证三件事：边界正确（同一句话各走各路，路由过程看得见）、有分寸（门控、冷却、预算，被理解但不被打扰）、建议由记忆驱动且一键应用（两个人说同一句话得到不同的建议）。
选旅程三条标准：高频真实（目标用户一周至少遇到一次）；座舱独占（手机给不了的体验，多系统的空间编排）；记忆差异可演示（换一个人说同一句话，出不同的建议）。

4.3 视觉原则与设置项
信息层级：场景名 ＞ 一句话摘要 ＞ 触发/执行折叠组 ＞ 主操作「应用」。默认摘要态，驾驶中只允许摘要态。
呈现位置与时序：主驾行驶中只走语音加 HUD 简条；停车或副驾场景才出中控卡片。一次只出一张卡，不排队不轮播，入场动效 300ms 内完成。
话术：TTS 不念卡片内容（用户看得见时不重复念）；轻量干预不超过 15 字；共情回复不夹带推销腔。
视觉风格：暗色座舱主题，卡片用品牌氛围色描边（舒缓为暖橙、纪念日为玫瑰色），按双屏座舱布局模拟。
demo 设置项：入口开关（语音弱意图 / 观察 / 全开）；信任级可视化；灯带开关（默认关）；判官宿主开关（门控独立模块，宿主在对话侧与场景大脑侧间切换，现场对比两案时序与输出质量）。
4.4 评测
弱意图触发：200 条中英样本的精确率（三态判对的比率）。
D1 双案对比：同一评测集下两案的上下文保真（建议是否体现对话上文）、时序、改造成本估算。
指标面板：呈现率、采纳率、拒绝率、打扰率四件套，加坍缩率与注入通过率；观察入口加影子模式重合率、晋升率。全部实时可视化。
4.5 工程组成与节奏
车辆客户端模拟（状态面板、卡片、语音气泡）；网关与语音识别用文本输入，可选浏览器语音；语义层用规则加小分类器，意图分档加场景域；中控分发表照 2.2 架构；车控快路径规则执行；闲聊用小模型答话；场景大脑用契约一次调用，配注册表、验证器、记忆包；状态服务可拨；记忆服务分型条目可看可删；场景引擎负责触发、执行、日志。

5. 未来展望（第三部分）
架构：端侧轻量适配器离线创建（观察挖掘与初判全车端化，行为数据不出车）；预筛并入既有语义理解层；舱内感知多模态信号进状态服务（困倦、分心、情绪状态）作为门控问二的输入；账号级跨车记忆，与场景传承 ▲ 汇合。
应用：车、手机、家的场景延伸（离家模式联动）；创作者包与季节包（场景可分享、可订阅、可创作）；区域包出海（本地化预设，隐私按当地框架预留数据边界）；口令分享。
产品化路径：demo → 概念评审（D1 决策加体验盲评结论）→ PRD 增补建议（显式入口放开、弱意图隐式触发新需求、记忆读接口、消息类型映射）→ 试点车型。

7. 横向关联能力
与场景编排 / 执行引擎：复用原子能力、场景卡片、执行与试运行管线；本方案是其「主动层」的前缀，不另建引擎。已有的「执行后参数自适应」是观察入口的种子形态（参数级、场景内闭环），观察入口把它升到场景级、全舱行为流。
与语音助手：助手形象是唯一化身，场景侧只占用状态词汇表；主动建议的语音呈现走既有播报通道；语音车控永远优先。
与记忆系统：情景、语义、偏好记忆是生成的素材，负面记忆是门控的一票否决项；新增记忆读接口一根线，其余全复用。
与消息呈现：全部主动呈现进统一消息仲裁（优先级、排队、抢占、驾驶中限提醒、方控应答），不另建弹窗。
与账号体系：场景随账号、车机手机双端同步、换车传承、家庭共享。
与硬件信号：能力层设计，不直接定义 CAN 信号；所需车辆状态经状态服务抽象获取。
与隐私合规：观察信号车端处理；感知只用事件不存画面；学习成果全透明可删可关；海外按当地隐私框架预留数据边界。
性能与可靠性：弱意图旁路对对话零感知（门控超时就放弃）；判断到呈现 3 秒内；确认响应 1 秒内；观察挖掘只在车端空闲时跑。
