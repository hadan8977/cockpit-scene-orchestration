# 座舱场景自动化编排：产品决策报告 v1

2026-09-02。依据：同事的 demo 文件、本次检索的公开资料、本次搭的评测套件。独立于此前所有文档。分项细节在同目录 01 到 06。

## 一、结论，先读这个

**判断**：做。但目标要从“一句话生成场景 JSON”改成“车认得生活里的时刻，提前布置好，说一句话，随时可撤销，越用越准”。demo 保留为编译前端；缺的是上下文信号、执行策略、信任机制、记忆、区域化。

**五个决定**
1. 做“场景引擎”这一档；“语音建宏”只是它的第一个里程碑；“座舱代理”不进量产。
2. 模型只在创建、建议、解释时运行；执行走车端规则引擎，毫秒级、可预期、断网可用。这也让模型可以按区域替换。
3. 第一批原子能力做四项派生语义：日历含调休与各国假日、昼夜、位置语义、天气。仅“工作日”一项，中国 2026 年按周几判断会错 25 天。
4. 主动要克制、可见、可撤销：每天最多一条建议，触发时说一句，60 秒内可撤销，撤销多了自动降级为先问。
5. 从第一天按“区域包”设计：能力用语言无关的 ID；假日、气候、天气与地图供应商、语言、法规策略、数据驻留、模型供应商都放进区域包，核心引擎全球一份。

**demo 的真实差距**：35 个条件全是舱内开关，没有时间、地点、人、天气、行程；数值条件没有比较符，多条件没有与或；能力名是中文字符串，出不了海。这是能力表和 schema 的问题，模型本身没问题。

**现在需要你的**：一把 dsv4flash 的 key；车端信号清单；首发市场顺序；demo 能力表来自哪款车型。

## 二、展开

**1. 用户要的是时刻，不是开关**

| 时刻 | 用户希望 | demo 能否表达 |
|---|---|---|
| 冬天工作日早晨上车 | 座椅方向盘已热、不起雾、播我常听的、导航去公司 | 只有前两项；不知道“早晨”“工作日” |
| 暴晒后上车 | 先排热气再制冷 | 有动作；不知道“刚上车”“晒了很久” |
| 后排孩子睡着 | 小声、暗灯、温度稳 | 有动作；不知道“孩子”“睡着” |
| 停车等人 | 舒服、别费电 | 大部分能；不知道“等人” |
| 车停外面要下雨 | 替我关窗并告诉我 | 不知道“下雨”“我不在车上” |
| 长假出远门 | 提醒补能、长途舒适 | 不知道“假期”“长途” |
| 换家人开 | 按她的来 | 不知道“谁” |

四种价值：少动手，上限低，AUTO 空调和记忆设置已吃掉大半；被照顾，情绪价值，依赖上下文信号；替我盯着，守护类，用户最愿意为“怕出事”留下 [推断]；是我的车，个性化与分享，理想论坛有车主一次分享 29 个任务码。

**2. 为什么现有场景功能不讨喜**

| 原因 | 我们的原则 |
|---|---|
| 设置成本高于回报 | 编辑器不是主路径，留给极客 |
| 做对了没感觉，做错了记很久 | 触发时说一句或出卡片，一键撤销 |
| 条件表达不了生活 | 先补派生语义，再谈自然语言 |
| 怕它突然动 | 动作分级，行驶中只做舒适类，新场景试用一周 |
| 没有“谁”在做 | 经语音助手的人格出口 |
| 越用越不准 | 撤销率高自动降级 |

反例保留：理想任务大师 40 多个条件、100 多项动作、海报扫码即装，极客用户确实喜欢编辑器；Alexa 的主动建议被大量用户搜“怎么关掉”；奔驰车主在论坛问“Routines 在哪”。

**3. 三档选项**

| 选项 | 用户感到 | 需要 | 建议 |
|---|---|---|---|
| A 语音建宏 | 一句话省几步 | 车控接口 | B 的第一个里程碑 |
| B 场景引擎 | 车认得我的生活 | 信号接入、规则引擎、语音出口 | 做 |
| C 座舱代理 | 像个人 | 车端算力或稳定网络、完整安全评审 | 研究 demo，不进量产 |

**4. 怎么做**
- 四条输入路径，成本从高到低：编辑器；一句话；“记住现在这样”，把当前舱内状态存成场景再问什么时候要；车主动建议，一次点头。
- 信任机制：说一句、60 秒撤销、试用一周、撤销率超三分之一降级、主动程度三档、行驶中只执行 A 类动作。
- 记忆五类：每人 8 字段偏好档案、地点、习惯、最近 7 天情景、场景统计；全部可见可删，访客不写入。
- 习惯挖掘不用机器学习：同时间桶、同地点类型、同星期类型重复 3 次且一致率 70% 以上就提一次建议。奔驰用约 8 次，车的场景一天只有一两次，8 次要等一周。
- 模型用在五处：一句话建场景、建议文案与起名、带档案解析模糊意图、情景压缩、预生成解释句。触发判断与执行不用模型。

**5. 原子能力三层与安全分级**
- L0 信号与执行器：车给什么就是什么，受车型信号清单约束。
- L1 派生语义：工作日、长假首日、返程日、通勤时段、昼夜、雨雪暴晒、家与公司、出发到达、长途、电量不够到目的地、停车等人、暴晒后上车、离车忘关窗、后排有人、谁在开车。每项是纯函数，带迟滞与冷却。
- L2 意图级能力：“舒服一点”“有氛围”映射到一组动作，需要档案，否则只是默认包。
- 安全分级：A 随时可自动，灯、香氛、座椅、空调、媒体、通知；B 仅停车或需确认，车窗开度大于 20%、门、尾门、座椅位置；C 不进动作表，挡位、关闭低速行人警报音、驾驶模式。demo 把“关闭低速行人警报音”放进了动作表，要拿掉。
- schema v2 增加：trigger 事件与 conditions 状态分开、比较符、与或、执行策略含只触发一次、冷却、迟滞、手动覆盖后静默、优先级、提示方式、撤销窗口、试用期，以及预生成的解释句和触发与撤销统计。demo 输出可无损映射。
- demo prompt 要修的 11 处已在评测套件的 P1 版本里修好，可与原版对比。

**6. 全球车型与区域差异**

做法：一个引擎，多个区域包。区域包含七样东西：假日与周末规则、气候季节包、天气与地图供应商、语言与单位、法规策略、数据驻留与同意流程、模型供应商。

| 维度 | 差异举例 | 产品准备 |
|---|---|---|
| 日历 | 中国有调休；沙特等海湾国家周末为周五周六，阿联酋 2022 年起改为周一到周五半天；斋月按阴历每年提前约 11 天；德国、美国假日按州不同；南半球季节相反；欧美有夏令时 | “工作日”“假期”“季节”全部按区域包计算，允许用户加个人假日 |
| 气候 | 北欧、加拿大要预热除霜；海湾、印度要预冷和防舱内过热；东南亚潮湿起雾发霉；欧洲花粉季；中东沙尘 | 季节场景包按气候带出，不做全球一套 |
| 法规：行人警报音 | 欧盟与联合国 R138、美国 FMVSS 141 要求电动车 AVAS 不可由驾驶员关闭；中国目前为推荐性标准 [待法规核实] | 全球统一从动作表移除 |
| 法规：自动关窗 | 美国 FMVSS 118、欧盟 R21 对遥控与自动关窗有防夹或距离限制 [待核实] | “下雨关窗”按市场配置是否允许远程执行 |
| 法规：分心 | 欧盟 GSR2 要求驾驶员注意力监测；Euro NCAP 2026 起对关键功能要求物理按键；美国 NHTSA 有分心指南；日本 JAMA 有显示规范 | 行驶中只播报不弹建议，卡片一行以内 |
| 数据与隐私 | 中国 PIPL 与汽车数据规定要求车内处理、境内存储、生物识别单独同意；欧盟 GDPR 与 2025 年 9 月起适用的数据法案；美国加州 CPRA、伊利诺伊 BIPA 对生物识别追责重 | 记忆本地优先，按区域分开存，档案不跨境同步；人脸默认关 |
| AI 与模型 | 中国生成式 AI 服务需备案，国产模型合规路径清晰；DeepSeek 在意大利、韩国等地曾被监管限制，海外用它处理用户数据有风险 [据 2025 年公开报道，需法务确认]；欧盟 AI 法案要求告知用户在与 AI 交互 | 模型供应商按区域可插拔，编译型架构让替换成本很低；同一套评测题集按语言本地化后重跑 |
| 网络安全 | 欧盟、日本、韩国的 R155 与 R156 已生效；中国 GB 44495 与 GB 44496 强制标准 2026 年起适用 [待核实日期] | 场景分享与导入要签名校验，远程执行要鉴权 |
| 语言与座位 | 英国、日本、印度、澳大利亚、东南亚多国右舵；华氏度、英里；12 小时制；中英夹杂 | 能力用 ID 不用中文字符串，“主驾”按市场映射到物理座位；单位随区域 |
| 生态 | 中国：米家、鸿蒙、微信车友群、高德与百度地图；海外：HomeKit、Google Home、Alexa、Matter、Reddit 与车主俱乐部、Google 与 HERE 地图 | 车家互联与分享渠道按区域接入 |
| 用车形态 | 海外租赁、共享、多司机家庭更普遍 | 账号制档案、交车即清除、访客模式 |

优先级：现在就能免费做的是能力 ID 化、区域包结构、派生语义参数化、模型可插拔；首发海外市场前要补该市场的假日与天气地图供应商、语言包、法务评审、气候场景包、右舵映射；宗教日历与跨区档案迁移放后。

**7. 参考对象的六条借鉴**
1. 编辑器不是主路径：奔驰三种创建方式里模板与 AI 学习占两种，Google 把 AI 生成放在专家脚本路径。
2. 主动要克制：Alexa 的教训。
3. 分享要参数化：理想海报扫码，Home Assistant 蓝图带参数。
4. 为别人创建：蔚来“副驾上车时开按摩并说加班辛苦了”，把控制变成关心。
5. 口令：蔚来的专属口令，场景名即口令。
6. 游戏与影视：FFXII 的 Gambit 让普通玩家愿意“编程”，靠语义化条件、看得见的触发、优先级排序、逐步解锁、即时验证；动森靠真实日历和“它记得你”；旅行青蛙靠“你不在时它做了什么”的报告。KITT 与 JARVIS 的可爱在开口时机和会提异议，HAL 的可怕在不可覆盖。

**9. 评测**
套件已建：56 题四类、原版与修正版两个 prompt、打分器，离线自检 100% 通过，噪声能检出。未对真实模型跑，现有 key 无效。要回答六件事：四类通过率、原版对修正版、思考模式开关的时延与通过率、重复 3 次的一致性、安全题、时延 p50 与 p95。上线门槛建议：能力表内 99%、动作类 95%、精准类 90%、安全违规 0、非思考 p95 不超 3 秒 [建议值]。模型成本可忽略，每万次创建约 2 美元以内。

**10. 不做清单**
不把模型放进执行路径；不先做场景市场，先做 4 个官方季节包；不自动关闭安全提示类功能；行驶中不把车窗开过通风缝；第一版不用人脸；不做“什么都能编排”，先做八个时刻。
