# 场景大脑落地方案 v5：接入现有架构、两种触发、能力热更新、最新路线

2026-09-03。依据你给的两张架构图：Gateway、ASR、TextNLU 与 Bert 微调 NLU、Master Agent 与任务拆解、Sub Agent（车控、地图、娱乐）、状态服务、记忆服务、TTS；中控分发按 domain 加 intent 加 currentAgentName 派发，其中 systemControl 加 CUSTOM_VOICE_SKILL_ENTRY 已经指向“场景大脑”。

## 一、结论

1. **场景大脑就放在你图里的位置**：中控分发的一个目标 Agent，与车控、地图、娱乐 Agent 平级。它自己不做分流，两种触发都由现有 NLU 和 Master Agent 完成，所以不需要再套一个路由模型。
2. **两种触发分开走**。显性触发（“我需要一个纪念日的场景”、场景名、“记住现在这样”）走 NLU 新增的 scene 域意图，直达场景大脑，currentAgentName 记为 scene_agent 以支持续聊。隐性触发（正常聊天里的潜在意图）走 Master Agent 的“旁听钩子”：Bert 微调层加一个二分类头判断“值得布景吗”，再看记忆与状态是否匹配，门槛高，异步出卡片，不碰主回复。
3. **场景大脑内部**：装配上下文，一次 LLM 调用，约束解码，验证器裁决，执行经现有 Sub Agent 当工具，场景经场景引擎持久化。
4. **能力热更新**：能力表不进权重，进注册表。prompt、约束解码的 schema、验证器都从注册表生成，紧急下线一条能力时三处同时失效，不重训。这一套已经做出来并演练过。
5. **最新路线的判断**：端侧小模型比 2024 年强得多，4B 以内做结构化输出与函数调用已经够用。但对你这个架构，端侧生成模型不是第一优先级：反射层就用你已有的 Bert 微调层，云端一次调用出场景；端侧生成只在离线创建场景时才需要，放第二阶段用蒸馏加 LoRA 适配器做，训练难度可控。
6. 两个例句“今天跑完步好累”和“我和她纪念日的场景”的完整走法见第三节。

## 三、落到你的架构上

**3.1 位置**

```
Vehicle Client → Gateway → ASR → Bert 微调 NLU（新增 scene 域；新增“值得布景”二分类头）
                                   │ domain, intent, currentAgentName, 布景分
                                   ▼
                         Master Agent / 中控分发
        显性：scene 域意图 ──────────────▶ 场景大脑（scene_agent）
        隐性：主域照常派发（闲聊、娱乐…）  ──▶ 主 Agent 答话
              同时旁听钩子命中 ──异步──▶ 场景大脑 suggest 模式 ──▶ 卡片
        车控域：重复组合计数（状态服务）──▶ 达阈值后 场景大脑 建议保存
                                   │
   场景大脑内部：装配上下文（状态服务快照 + 记忆包 + 注册表子集）→ 一次 LLM 调用（约束解码）→ 验证器 → 卡片 / 执行 / 保存
   执行：车控 Agent、娱乐 Agent、地图 Agent 当工具；场景引擎持有触发条件；统计与记忆回写记忆服务
```

**3.2 显性触发**。NLU 新增 scene 域，四个意图：SCENE_CREATE（“我需要一个跑步后的场景”“帮我弄个纪念日的氛围”）、SCENE_RUN（场景名、口令）、SCENE_SNAPSHOT（“记住现在这样”）、SCENE_MANAGE（改、删、列）。中控分发把它们全部派给场景大脑，并下发 currentAgentName 等于 scene_agent，续聊时“再暗一点”“换首歌”回到场景大脑。现有的 CUSTOM_VOICE_SKILL_ENTRY 保留为 SCENE_RUN 的别名。样例话术中英各 200 句起，我来出。

**3.3 隐性触发**。旁听钩子放在 Master Agent 分发之后，五个条件全部满足才调场景大脑：

| 条件 | 说明 |
|---|---|
| 主域不是命令类 | 车控、导航、电话这类直接命令不布景；只对闲聊、娱乐、用车助手等域旁听 |
| 布景分不低于 0.8 | Bert 层的二分类头，训练数据是“会不会因为这句话想调整环境”的标注，中英各 2 千句起 |
| 记忆或状态有匹配 | 记忆服务里有相关习惯或关系事实，或状态服务显示运动后、深夜、停车、长途之一 |
| 预算未用完 | 每周卡片不超过 2 张，同类被忽略两次停 30 天，静默学习期内不出 |
| 非高负荷驾驶 | 车速与转向状态来自状态服务 |

命中后异步调用场景大脑的 suggest 模式，主回复不等待；卡片 8 秒无操作退场。误报比漏报贵，所以阈值先高，宁可不出。

**3.4 场景大脑内部**。四步：装配上下文，状态服务快照加记忆包不超过 300 token 加注册表子集（按这句话检索 top-k 能力，减少 prompt）；一次 LLM 调用，P3 契约，用注册表生成的 schema 做约束解码，understanding 字段不受约束先写；验证器按注册表版本裁决；输出卡片、立即执行或保存场景。执行走现有 Sub Agent：车控 Agent 执行动作，娱乐 Agent 播歌，地图 Agent 承接 offer 里的导航；场景保存后触发条件由场景引擎持有；触发与撤销统计回写记忆服务。

**3.5 两个例句的完整走法**

| 步骤 | “今天跑完步好累”（隐性） | “我和她纪念日的场景”（显性） |
|---|---|---|
| NLU | 主域闲聊；布景分 0.86 | scene 域，SCENE_CREATE |
| 中控分发 | 闲聊百科答话“跑完啦，辛苦”；旁听钩子命中 | 直达场景大脑，currentAgentName 等于 scene_agent |
| 状态服务 | 19:40，停车转出发，车外 31 度，主驾有人 | 停车中，副驾无人 |
| 记忆包 | 周二周四 19:30 前后从健身房出发，20 分钟到家；跑后习惯通风 2 挡；常听播客 | 她等于小雨；纪念日 10 月 12 日；你们的歌《晴天》；喜欢暖光；不喜欢太浓的香氛 |
| 一次调用 | understanding“跑完步累，天热，要凉快和轻松”；动作：主驾通风 2 挡、温度 23、音乐播放放松（或播客续播）、氛围灯 30%；say“辛苦了，二十分钟到家”；offer none | understanding“为小雨准备纪念日，用你们的歌和暖光”；动作：氛围灯 30%、音乐播放浪漫（曲目《晴天》）、香氛淡雅、温度 24；say“纪念日快乐”；offer none |
| 验证器 | 停车中，无裁剪 | 行驶时律动会被裁掉；此处停车，无裁剪 |
| 输出 | 卡片“跑步后”，采纳即执行；采纳两次后建议保存并挂触发：周二周四 19:00 到 20:30 从健身房出发 | 卡片“纪念日”，三个按钮：现在用、保存、10 月 12 日她上车时自动用 |
| 续聊 | 无 | “再暗一点”回到场景大脑改亮度 20% |
| 记忆回写 | 采纳：preference“跑步后接受布景” | 保存场景；不新增记忆 |

## 四、能力热更新与训练难度

**4.1 原则**：能力表不进权重。注册表是唯一来源，三处从它生成：prompt 里的能力表、约束解码的 JSON schema、验证器的闭集与禁止值；场景引擎执行前再查一次注册表状态。

**4.2 已做**：`eval/registry.py` 提供 build、list、enable、disable、render、schema 六个命令；`capabilities.json` 56 条能力，每条有 ID、中英名、分组、安全级、状态、禁止值、备注；`schema.json` 供约束解码。演练：下线主驾车窗后，重新渲染的 prompt 里没有它，schema 里没有它，验证器把含它的动作丢掉并标注“能力已下线”。全程不碰模型。

**4.3 三种变更**

| 变更 | 云端一次调用 | 端侧生成模型（若做） | 已保存的场景 |
|---|---|---|---|
| 紧急下线 | 注册表置 disabled，三处立即失效 | schema 与验证器拦住，权重不动 | 引用该能力的场景自动暂停，卡片告知 |
| 新增能力 | 注册表加一条，附描述与两三个示例，立即可用 | 按“看描述就能用”的泛化训练，先降级可用，月度 LoRA 刷新 | 无影响 |
| 改值域 | 改注册表，schema 随之改 | 同上 | 越界值由验证器取边界 |

**4.4 训练难度**

| 项 | 数据 | 算力 | 交付 | 难度 |
|---|---|---|---|---|
| Bert 层加 scene 域与布景头 | 意图中英各 200 句起，布景标注中英各 2 千句 | 单卡小时级 | 你们现有 NLU 发布流程 | 低 |
| 端侧 LoRA SFT，0.6B 到 1.7B | 云端模型蒸馏 2 万条中英样本 | 1 到 4 卡数小时 | 适配器 100 到 200 MB，OTA | 中 |
| GRPO 收尾 | 验证器当奖励，不需要标注 | 1 到 2 天 | 同上 | 中 |
| 全量微调或预训练 | 不做 | 不做 | 不做 | 不值 |

**4.5 回归**：每次注册表变更跑 74 题中英加 8 道注入题，门槛沿用 v4。

## 五、对实验与计划的调整

- E4 端侧可行性改成两段：第一段是 Bert 层加 scene 域和布景头，两周内可上；第二段端侧生成模型放第四周后再定。
- 新增 E7 隐性触发评测：借 ContextAgentBench 的格式，造 200 条“聊天加状态加记忆”的样本，中英各半，标注该不该出卡片，看精确率优先。
- 六周计划第 2 周的骨架改为接 Master Agent 的两个接口：scene 域派发、分发后异步调用加推卡片；不再做独立旁听通道。

## 六、要确认的三件事

1. Bert 微调层能否加一个 scene 域和一个二分类头，样例话术我来出。
2. Master Agent 能否在分发之后异步调用第二个 Agent 并向车机推卡片，不影响主回复。
3. 记忆服务的读写接口和分型：有没有来源、范围、保留期、同意四个字段，没有的话我给一版结构。
