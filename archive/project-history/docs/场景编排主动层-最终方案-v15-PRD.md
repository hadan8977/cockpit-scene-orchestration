## 1. 产品概述

### 1.1 产品背景

今天的座舱只响应说出口的指令。强意图与弱意图里的业务表达走车控快路径，"打开空调""我好冷"秒级完成；弱意图里的非业务表达落进闲聊，"我好累"只换回一句共情；显式的场景请求"给我生成一个累了以后的场景"被锁在编排页面内，不进页面就触发不了 [据 PRD 3.6.2，kimi 核实]。三条路都要求用户先想到、再说出、再配置。

能力侧已经齐了：四档意图的语音路由、六类记忆、状态服务、96 条原子能力（2026-07 能力表，含生效范围、声场、小塔播报、延时、情景模式、彩蛋）、能带触发条件的场景引擎，执行后 10 分钟参数自适应也已规划 [据 PRD，kimi 核实]。缺的是把"理解"接到"出手"的一层：谁来判断这句话、这个习惯、这个时刻值不值得布置一个场景，用什么形式给，给了以后怎么升级为无感自动、怎么保证不烦人、怎么保证安全。

本方案在场景编排之上加这一层，叫主动层：五个入口进来，一道门控判断，场景大脑一次调用生成，呈现调度按信任级给出六种形式之一，场景引擎单点执行，反馈进负面记忆与信任账本。方案分三部分：第一部分生成框架，现在就能开做，也是第二部分的底座；第二部分产品需求与 demo，本 PRD 的主体；第三部分未来展望。

### 1.2 产品价值及体验目标

**看行业**。奔驰、宝马、蔚来、理想、小鹏、华为都已把"主动"写进座舱，做法集中在单动作级：推一张瓷片、问一句、直接开个窗。没有人把主动和可编排的组合能力接通。编排级主动智能，一次理解、多步组合、可升可降、可解释可撤销，是有场景引擎的玩家才有资格做的位置。对标明细见 1.4。

**看用户**。多任务组合传统模式要 8 到 10 次交互，场景化后 1 到 3 次；主动层再省掉"先想到、再说出、再配置"三次隐性成本。不看预设时用户的需求只有八个词：被记得、被照顾、被理解、不被打扰、有惊喜、有掌控、能炫耀、能安心。离场时要记住三句话：它懂我但不烦我；它居然记得；一切我说了算。

**看企业**。行为记忆加场景资产越用越厚，换车成本随之上升；观察入口沉淀"用户为什么这么做"，比埋点深一层；主动建议到采纳到分享，给场景生态一条自增长通路；运营从"云端推模板"升级为"替用户生长场景"。

### 1.3 名词解析

| 关键词 | 定义 |
|---|---|
| 弱意图 | 表达状态、目标或情绪，不是动作指令；业务类落车控，非业务类落闲聊 [据 PRD 四档意图] |
| 场景 | 有名字、可复用、可带触发条件、可编辑可分享可学习的动作组合，六元素：光、声、气、温、话、供；庆祝类多一个惊喜（彩蛋）。话由小塔播报承接，先后顺序由延时动作承接 |
| 成熟度 | 注册表每条能力的状态：已上车、有能力无 UX、排期中、待定、提议。prompt 里后三种标注，验证器分量产档与 demo 档 |
| 场景大脑 | 编排内容的唯一生成者，一次调用同时输出相关度、意图、理解句、场景、话术、记忆提议 |
| 一次调用契约 | 场景大脑的输入输出结构，五个入口共用，见附录 C |
| 注册表 | 原子能力闭集清单，从公司能力表导入，含中英名、分组、安全级、成熟度、禁止值、状态、执行映射；prompt、约束解码 schema、验证器白名单都由它生成。派生条件（时段、星期类型、位置、天气、行程事件）也在表内，只作条件 |
| 出厂守护清单 | 不需要用户先确认就允许静默执行的 A 级守护动作，出厂内置、首次交车告知、设置里可关；清单见 3.8 |
| 评测门 | prompt 与模型版本的上线门：双路体验门（机器评审加人工盲评）加硬指标，见 2.4 |
| 验证器 | 模型外的裁决层：结构、闭集、安全禁止值、行驶策略、动作数、话长、注入标记 |
| 安全级 | A 随时可自动；B 仅停车可自动或需确认；C 不进自动化动作表 |
| 条件语义层 | 由原始信号派生的可读条件：工作日含调休、昼夜、暴晒后上车、停车等人等，见 2.3.4 |
| 五入口 | 显式语音、弱意图语音、观察、时刻、物理与顺手 |
| 门控 | 所有主动出手的唯一判断通道：问零显著性，只对观察入口；问一能不能接；问二此刻合不合适；问三值不值得 |
| 建议对象 | 门控与呈现之间的契约：来源域、类型、风险级、价值分、紧急度、过期时间、允许形式、信任级、一键动作、撤销动作、解释一句 |
| 呈现调度 | 时机与形式的决定者，预算按整车算；宽版归语音助手方向，本期做只管场景类建议的窄版策略 |
| 信任阶梯 | L0 静默学习、L1 顺手提示或一句话询问、L2 卡片、L3 计时器确认、L4 静默执行加事后一句 |
| 分寸预算 | 整车共享的主动打扰限额账本，含云端运营推送 |
| 观察入口 | 从手动操作序列、车辆状态、舱内感知里统计挖掘习惯模式的入口 |
| 影子计数 | 候选模式先只记不做，统计"如果启用会在何时触发"与用户实际行为的重合，达标才获呈现资格 |
| 反向学习 | 统计"用户总是关掉什么"，生成负规则 |
| 负面记忆 | 拒绝、撤销、总是关掉沉淀成的一票否决项，记忆包里优先注入 |
| 记忆包 | 每次生成注入的记忆摘要，上限 300 token，负面记忆优先 |
| 顺手提示 | 出现在用户正在操作的面板上的一行字，一键即存 |
| 计时器确认 | 通知加 15 秒倒计时，不取消即执行，方控键可应答 |
| 试演三秒 | 应用前只动灯与声预演三秒，说"就这样"或"不用" |
| 一键恢复 | 执行前状态快照，一句"还原"回到执行前 |
| 存在感通道 | 场景大脑向助手形象层发的五种状态：有想法、在试演、在执行、学会了、被撤销 |
| 坍缩率 | 输出与任一预设完全一致的比例，反映模型偷懒，越低越好 |
| 注入通过率 | 注入类样本中有任一动作被执行的比例，必须为零 |

| 规律 | 来源 | 落法 |
|---|---|---|
| 主动的终点是静默执行加可见的规则 | Alexa 四分之一家居交互由它发起；宝马学会进公司停车场就开窗；特斯拉过热保护 | L4；"它学会了什么"页 |

| 应用前可改 | Google Home 建议自动化 | 卡片与提示带"改一下" |

| 状态类建议限低频、高价值、单动作 | 理想主动推荐空车位与超充；问界三个量产推荐场景 | 时刻入口只做守护与省事类 |
| 主动内容可点踩 | ChatGPT Pulse | 每条建议带"不要这类" |
| 存在感归助手 | NOMI 用表情与转头表达决策；奔驰星形头像 | 存在感通道 |
| 数据留端侧 | Magic Cue、三星 Now Brief | 挖掘车端优先，感知只用事件不存画面 |

### 2.2 整体功能与架构

**2.2.1 在现有语音架构上的位置**。主动层不新建管线，改四根线、加三个模块。

```
车辆客户端 -- 网关 -- ASR -- NLU(Bert 微调) [改1: 新增 scene 域四意图与布景分]
                                |
                     Master Agent / 中控分发 [改2: 闲聊域命中布景分时异步旁路到场景大脑]
        +-----------+-----------+-----------+---------------------------+
     车控 Agent   地图 Agent   娱乐 Agent   闲聊 Agent      场景大脑 (Sub Agent)
        |           |           |           |  --异步旁路-->   |- 注册表 -> prompt / schema / 验证器  [加1]
        +-----------+-----------+-----------+                  |- 记忆包 <= 300 token
              ^ 执行经现有 Sub Agent 当工具                      |- 一次调用 -> 建议对象
     状态服务(RW) --- 记忆服务(RW) [改3: 场景大脑读接口] --- 观察挖掘(车端空闲时) [加2]
     场景引擎(触发 / 执行 / 快照 / 日志) --- 呈现调度(窄版策略, 挂在消息仲裁) [加3] --- 助手形象 / TTS / HUD / 卡片 [改4: 存在感通道]
```

四根线：NLU 加 scene 域；Master Agent 加异步旁路；记忆服务开读接口；助手形象接存在感通道。三个模块：注册表加验证器，进场景大脑；观察挖掘，跑在车端；呈现调度窄版策略，挂在既有消息仲裁里。

**2.2.2 数据流**

```
显式语音 ----------------------------+
弱意图语音 --> 门控(问一到问三) ------+--> 场景大脑一次调用 --> 呈现调度 --> 场景引擎 --> 反馈
观察入口 ----> 问零 --> 门控 ---------+        (注册表 / 记忆包 / 验证器)   (信任级定形式)  (单点执行, 快照)   (负面记忆 / 信任账本 / 埋点)
时刻入口 --------------------------------------------------------------------> 场景引擎
物理与顺手入口 ------------------------------------------------------------> 场景引擎
```

时刻与物理入口是用户已确认规则的再触发或就地授权，不经门控，但执行同走场景引擎，进同一套信任与预算记账。

**2.2.3 三条原则**

- 入口多，判断成漏斗，呈现单点：每一级判断只能说"不"，只有呈现调度能决定"出"和以什么形式出。判官放对话侧还是场景大脑侧都不会产生两套答案。
- 生成复用，执行复用：不新建生成器与执行器。场景大脑加意图分支，场景引擎照常执行；车控、地图、娱乐 Agent 是工具。
- 状态与表现分离：场景大脑只发状态，不占任何一种表现形式；助手形象是全车唯一化身。

**2.2.4 三份契约**。一次调用契约，场景大脑的输入输出，附录 C；建议对象契约，门控到呈现，字段见 1.3；存在感状态，五个词。契约由本方案定义，各域共用，宿主可换。

### 2.3 技术路线

**2.3.1 总体决策**

| 决策点 | 结论 | 依据 |
|---|---|---|
| 要不要单独训路由模型 | 不训。一级判断复用 NLU 已有的域、意图、置信度加一个布景分头；终审在一次调用里 | 级联小模型增加维护面 |

**2.3.2 语音入口：显式、强意图与弱意图**

边界三判据：组合度，要动两个以上元素，主判据；持久性，留下可复用对象；表达类型，说的是状态或目标。两条上位规则：安全表达先走安全与车控的固定动作，场景大脑不在安全情境里创作；指令式的组合直接做，陈述式的弱意图才走门控。

| 话 | 去向 | 形式 |
|---|---|---|
| 热死了 | 车控 Agent，MAX AC | 直接做，不出卡 |
| 有点困 | 安全与车控固定提神动作 | 直接做，语音建议休息 |
| 别吵醒他 | 场景大脑立即布景：声场切前排、音量、氛围灯、导航音量 | 直接做，不说话 |
| 她说还要二十分钟 | 闲聊答话；场景大脑异步判断 | 一句话询问，同意后试演 |
| 做一个雨夜回家的场景 | 场景大脑，scene 域直达 | 卡片，可改可存 |

显式入口：NLU 新增 scene 域四意图，SCENE_CREATE、SCENE_RUN、SCENE_SNAPSHOT、SCENE_MANAGE，中控分发派给场景大脑并把 currentAgentName 记为 scene_agent，续聊"再暗一点"回到场景大脑；现有 CUSTOM_VOICE_SKILL_ENTRY 作为 SCENE_RUN 的别名。002 的七条句式已覆盖，只需放开"仅编排页内"的触发条件 [据 PRD 3.6.2]。

弱意图旁路时序：

```
用户 "她说还要二十分钟"
  -> NLU: 闲聊域, 布景分 0.9
  -> 中控分发 -> 闲聊 Agent -> TTS "那先歇会儿"            (1.5 秒内, 与现状一致)
             \-> 异步: 门控问二(停车, 预算有, 无冷却)
                   -> 场景大脑一次调用(问三: 相关度 0.85, 生成"等人"场景)   (3 秒内)
                   -> 验证器 -> 建议对象 -> 呈现调度(L1) -> 助手一句话询问
```

判官宿主 D1，两案共用同一门控逻辑与同一建议对象，demo 里一个开关切换：

| | A 案：对话侧判断 | B 案：场景大脑自判 |
|---|---|---|
| 做法 | 闲聊答话的同一次调用多输出三个字段：要不要、置信度、理由 | 闲聊只答话；query 加最近两轮加记忆命中打包转给场景大脑，生成调用里自判 |
| 长处 | 对话上下文无损；能感知用户不耐烦即时冷却 | 判断与生成一次完成；场景大脑有注册表，能答"车帮不帮得上" |
| 代价 | 改闲聊 Agent 的 prompt 与输出，每句闲聊多付时延 | 对话上下文要作为字段传递 |
| 前提 | 语音侧接受闲聊 Agent 改造 | 记忆读接口，一周量级接入 |

产品倾向 B 案，改动集中在场景大脑一处；证据由 demo 的同一评测集给出：上下文保真、时序、改造成本。

**2.3.3 观察入口：从行为到场景**

```
手动操作序列 ---+
车辆与环境状态 -+--> 车端统计挖掘(空闲时每日一次) --> 候选(3 次以上, 一致 70%, 2 元素以上)
舱内感知事件 ---+                                        |
                                    影子计数(最多 7 天) --达标--> 门控问一到问三 --> 顺手提示(L1)
                                                        --不达标--> 丢弃
反向学习: "上车后总是关掉 X" 达同样门槛 --> 负规则 --> "它学会了什么"页
```

每次手动操作记为条件元组加动作集合，元组取时段、地点类、星期类型、天气、乘员构成五项。候选交给场景大脑同一次调用，intent 记为 observation，条件由挖掘预填，模型只补理解句、命名与话术。影子计数把显著性从概率变成事实，提示时可以说"过去一周有 5 天你都这样做了"。挖掘在车端跑，行为数据不出车；舱内感知只用事件不存画面。

**2.3.4 时刻入口：条件语义层**

| 一 | 时段、昼夜 | 生效范围的时间段；天黑可用近光灯开启代理 | 已有 |

**2.3.5 物理与顺手入口**。长按控件或方向盘键"记住现在这样"：取当前状态与常用基线的差异存为场景，问一次"什么时候要这样"，给三个基于当前条件语义的候选触发。顺手提示由观察入口驱动，出现在用户正在操作的面板上。两者都不经门控，直接落场景引擎。

**2.3.6 生成与约束**

意图分六类：action 动作、precise 精准条件、vague 模糊目标、affect 情绪、observation 观察候选、clarify 追问，外加 none。场景按六元素语法组合：光、声、气、温、话、供。反坍缩五条：prompt 里不放预设清单；先写理解句再写动作，理解句必须引用原话；示例结构互不重复且含"只说一句"与"只做一件事"；预设只用于离线兜底与反射层首动作；坍缩率作为上线指标，目标低于 30% [设计值]。规则类场景要确定性，创作类要多样性，两套采样配置分开。

硬约束五层，prompt 是第零层：

| 层 | 管什么 | 例子 | 状态 |
|---|---|---|---|
| 注册表 | 能力闭集、派生条件、安全级、成熟度、禁止值、上下线、区域值 | 下线香氛后三处同时失效；行人警报音表里允许关，本方案禁止 | 已做，96 条 |
| 约束解码 | 模型物理上写不出表外能力与非法取值 | 动作只能取 enum | schema 已生成；harness 有严格 schema 开关，各家支持度由第一轮评测给出 |
| 验证器 | 安全禁止值、行驶策略、动作数、话长、去重、注入标记 | 关行人警报音被丢弃并标法规；行驶中车窗改一小缝 | 已做 |
| 执行策略 | 执行前再查注册表、冲突消解、快照、超时熔断 2.5 秒降级话术、全程日志 | 试演后才落座椅动作 | demo 内做 |
| 评测门 | 74 题中英、8 道注入、坍缩率，达标才上线 | 注入失分不为零即不上 | 已做 |

**用户看到的。** 场景 app 里一个输入框；0.6 秒内先出理解句，引用原话；六元素 chips 逐个出现；表外能力灰显"做不了"，被验证器裁掉或改值的 chip 灰显带理由；三个键：就这样、改一下、不用；再说一句只改一处。试演三秒依赖场景引擎与灯声通道，归第二部分。内部版多一个模型与 prompt 下拉框、一条真实时延条、一列路由与裁决。原型页已有，回放评测运行里的真实输出，不调模型。

**选型三关。**

一关，体验门，双路。机器路：评审模型对情绪、模糊、弱意图、记忆、显式、观察、追问七类输出打四项分（贴切、分寸、话术、密度，1 到 5）并给六个旗标（说教、推销、追问原因、假设关系、复述情绪、功能性误用）；评审模型与被评模型不同。人工路：36 句盲评集覆盖七类，候选匿名随机排序，全量由产品评，另抽 12 句由决策人评，同一评分表；两路对照一致性。门槛：四项均值不低于 3.5 且任一项不低于 3.0，人工路首选次数作并列依据 [设计值]。服务项四条一并看：续聊改一处、表外走 unsupported、三次重复结构一致、中英一致。任一项不及格出局。

二关，硬指标：能力表内 99%、动作类 95%、精准类 90%、注入通过率 0、relevance 落在期望区间 90%、理解句出齐 p50 0.6 秒、非思考总时延 p95 2 秒、中英通过率差不超过 5 点、坍缩率精确低于 30%（只算情绪与模糊类）。情感类贴切不再用百分比，以机器路贴切均值代替。

三关，成本，只用于排序。

**变量。** prompt 六变体：p0 原版、p1 修正 schema、p2 情绪与档案、p3 六元素语法（注册表渲染）、p3-r 示例轮换版、p3-neg 负面记忆强化版；思考开关；输出格式 text、json_object、json_schema；语言中英；温度 0，个别端点按其限制。

**产出。** 注册表渲染的 prompt、一页约束文档、一页选型报告、原型页（回放选定模型的真实输出）、原型设计 prompt、scene 域 200 句语料初版（由题集显式与弱意图两类扩写）、盲评表与两路一致性。

**节奏。** key 到位算 D1：D1 核对 id 并跑第一轮全部候选（p3、非思考、中英、一遍）；D2 机器评审与盲评表，决策人评 12 句；D3 第二轮只对过门模型跑思考开关、六变体、严格 schema、重复三遍；D4 写 p3-r 与 p3-neg 复跑；D5 选型报告一页、原型换成选定模型、PRD 增补。

**冒烟给出的两条修正方向。** 一个可用端点上的 32 句新题类冒烟：题级通过 81%，观察与追问全过，弱意图 75%，记忆 63%。失败集中在两处：模型把示例里的一组动作搬进不相干的场景，动作偏多；被拒绝过两次的场景又给了三个动作。分别对应 p3-r 与 p3-neg 两个变体。该端点时延不作参考。

**评审意见的处理。** 六处评审问题在本版的落点：旅程一第 9 拍与信任阶梯的矛盾，补出厂守护清单（1.3、3.8、4.2）；试演进了第一部分，移回第二部分（本节、3.1）；评测门四项测不了，理解句时延定测法、坍缩率限分母、情感贴切改评审分、契约字段补题（本节、3.4、附录 C、附录 D）；候选模型以拿到 key 为准并分档（本节）；布景分训练语料没人认领，200 句由题集扩写并在第一部分交付（附录 A）；多乘员音区归属无信号，在 7 章硬件信号处写明待确认。

### 3.18 异常情况汇总

判断层不可用：全部入口退回被动模式，宁可静默不乱出手。生成异常：弱意图路径静默吞掉，观察候选下轮重出，显式创建降级话术。执行异常：快照兜底一键恢复，异常率高的场景类型冻结爬坡。注入与越权：闭集约束解码、表外走 unsupported、注入置 none，全部在验证器不在 prompt；分享导入的场景文本同样过验证器。

## 4. demo（第二部分的体验验证）

### 4.1 目标与旅程选择

demo 让人相信三件事：边界正确，同一句话各走各路，路由过程看得见；有分寸，门控、冷却、预算，被理解但不被打扰；建议由记忆驱动且一键应用，两个人说同一句话得到不同的建议。旅程按四条标准选：高频且全球通用；车当房间用的时刻，编排才有空间；能同时演边界与分寸；不用个人化的偶发例子。选定的时刻：暴晒后上车与堵车做边界对照；后排孩子睡了；地库等人；周六造一个雨夜回家的场景；四个晚上的到家习惯。等人与接送孩子是停车与低速时段里最常见的两个时刻 [推断，需用车日志验证]。

### 4.2 三条旅程

旅程一「一个傍晚」，弱意图主线：边界、门控、多乘员、时刻入口、收件箱。

## 7. 横向关联能力

与场景编排与执行引擎：复用原子能力、场景卡片、执行与试运行管线；本方案是其主动层前缀，不另建引擎；已有的执行后参数自适应是观察入口的种子形态，升到场景级与全舱行为流 [据 PRD 场景编排需求表]。

与语音助手：四档意图与随心车控不变，"我好冷"仍走车控 [据 PRD 3.4.1]；NLU 加 scene 域与布景分；助手形象是唯一化身；主动建议的语音走既有播报通道；语音车控永远优先；宽版呈现调度归语音 PRD 已认领的小塔主动推荐方向，本方案提供契约与窄版策略 [据语音 PRD 看机会]。

与记忆系统：六类记忆是生成素材，负面记忆是否决项；新增场景大脑读接口一根线；操作行为记忆提取 P2 与观察入口对齐 [据小塔记忆 PRD 3.2.5.3、3.4.6]。

与消息呈现：全部主动呈现进统一消息仲裁，优先级、排队、抢占、驾驶中限提醒、方控应答，不另建弹窗；需核实 HMI PRD 的通知中心与免打扰策略 [待 kimi 核实]。

与运营推荐：云端圈选推荐场景走量，观察入口走个体；撞车时个人级压运营级；两者共用预算账户 [据场景编排 PRD 规划列]。

与账号体系：场景随账号，车机手机双端同步，换车传承与家庭共享放展望。

与硬件信号：能力层设计，不直接定义 CAN 信号；所需状态经状态服务抽象。按 2026-07 能力表：锁车事件有（车锁全部上锁）；后排占位无，用后排安全带代理；天气无，需接云端天气服务；导航剩余距离与到达时间已删除；多音区声源定位无，旅程一第 3、4 拍"副驾说"在 demo 里可拨，量产前需确认。

与隐私合规：观察信号车端处理；感知只用事件；学习成果可删可关；区域包决定同意流程与保留期。

性能与可靠性：弱意图旁路对对话零感知；判断到呈现 3 秒内；确认响应 1 秒内；场景执行 300 毫秒内；挖掘只在车端空闲时跑。
